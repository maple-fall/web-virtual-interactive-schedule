## 一、产品缺陷

### 1. 时间区间终点丢失时段前缀【开发者：】

**现象**：输入「明天下午2点到4点开会」，落库成 `14:00 – 次日 04:00`，正确应为 `14:00 – 16:00`。

**根因**：`parseWhen()` 的区间分支里，起点「下午2点」带时段前缀，终点「4点」没有；`findTime` 只对起点应用了 `applyPeriod`，终点按 24 小时制直读成 04:00，`Manager.add` 再按「结束早于开始」判成跨天。

**修复**：终点没有自己的时段词时，继承起点时段；但只在「继承后终点晚于起点」时采纳，避免把真想跨夜的「晚上10点到2点」改成 `22:00–14:00`。

**验证**：`test-parse-time.js` 覆盖 7 组对照（下午/上午/晚上/中午、自带前缀、跨夜、无前缀），全部通过。

**详见**：[开发记录 二](desktop-pet-开发记录.md#二时间区间终点省略时段前缀的解析修复)

### 2. 「晚」单字与「今晚 / 明晚 / 后晚」不识别【开发者：】

**现象**：「晚8点到9点」被当成早上 8 点；「明晚8点到9点」不仅时间错，标题里还残留一个「明」字。

**根因**：`PERIOD` 词表只有「晚上」，没有口语单字「晚」和自带日期的「今晚 / 明晚 / 后晚」。另外 `stripSpans` 遇到重叠 span 时直接丢掉后一个，导致「明晚」的日期 span 吃掉「晚」后，时段 span 被丢弃、`8点` 留进标题。

**修复**：

- `PERIOD` 增加 `晚`，并把 `今晚|明晚|后晚` 放在 `晚` 前面整体匹配；
- `applyPeriod` 与 `findDate` 补上这三个词的日期偏移；
- `stripSpans` 的重叠处理从「丢掉后一个」改为 `cursor = max(cursor, s.end)`，让重叠部分正常吞掉。

**验证**：`test-parse-time.js` 新增 4 条「晚」用例；真机 e2e 新增「明晚」用例，均通过。

**详见**：[开发记录 3.1](desktop-pet-开发记录.md#三晚字缺失娱乐词宽松匹配壁纸背景分家)

### 3. 娱乐词被修饰语隔开就匹配不上【开发者：】

**现象**：「我想玩一会儿游戏」「我想看个视频」「想刷会儿手机」不会触发娱乐拒绝。

**根因**：`refuse` 的判定是整句子串扫描，精确关键词能命中，但动词和宾语之间插入修饰语后就断了。

**修复**：`App.Config` 增加一组宽松正则，动词与宾语之间允许最多 4 个字符；命中后用规范词（如「玩游戏」）作为标题，避免标题变成「玩一会儿游戏」。刻意不收 `看…剧`，因为「看剧本」是正经事。

**验证**：相关离线套件与真机娱乐拦截时间线（`alert` → 用户请求 → `refuse`）均通过。

**说明**：拒绝只在任务进行中触发；空闲时的娱乐请求走安抚分支，不是没识别出来。

**详见**：[开发记录 3.2](desktop-pet-开发记录.md#三晚字缺失娱乐词宽松匹配壁纸背景分家)

### 4. 壁纸面板混进舞台背景图【开发者：】

**现象**：`data/wallpapers/` 只有一张图，换壁纸面板却显示两张。

**根因**：`WALLPAPER_PRESETS` 里多了一条 `data/backgrounds/bg1.jpg`（舞台背景），和壁纸预设混在了一起。

**修复**：删掉这条预置，并在注释里写明「壁纸预设只收 `data/wallpapers/`」。`sanitizeWallpaper()` 的白名单随之收紧——把舞台背景路径当壁纸设置会被拒绝。

**验证**：`test-wallpaper.js` 60 条通过，新增「预设不含背景图」「背景图当壁纸被拒」两条断言。

**详见**：[开发记录 3.3](desktop-pet-开发记录.md#三晚字缺失娱乐词宽松匹配壁纸背景分家)

### 5. 「下载模板」在 `file://` 下失效【开发者：】

**现象**：点击「下载模板」没有文件落盘，页面反而跳到 PDF。CSV 时代正常，换成 PDF 后暴露。

**根因**：HTML 的 `download` 属性只在同源 URL 上生效；`file://` 下每个本地文件都是独立 opaque origin，链接属于跨源，属性被忽略、退化成普通导航。Edge 内置 PDF 阅读器又把 PDF 渲染在当前标签页，于是页面被顶掉。CSV 之所以正常，只是因为浏览器无法内联渲染 CSV，只能下载——巧合掩盖了 bug。

**修复**：

- 模板字节随 `schedule/scheduleTemplate.js` 一起加载进内存（`file://` 下 fetch/XHR 都读不了本地文件）；
- `<a download>` 换成按钮，点击时用 `Blob + createObjectURL` 再触发下载；
- `App.util.downloadBlob()` 统一处理临时链接与 `revokeObjectURL()`。

**验证**：真 Edge + CDP 断言「点击后页面没有导航走」且「落盘字节与模板 PDF 逐字节一致」；`test-pdf-import.js` / `test-timetable-import.js` 回归通过。

**详见**：[开发记录 九](desktop-pet-开发记录.md#九下载模板失效file-下的跨源-download)

### 6. 多轮闲聊逐字复读【开发者：】

**现象**：连续问「你好」「现在是几点」「你是什么模型」「你可以翻译英语吗」，四问得到同一句话；第二轮的回答是上一轮 assistant 回答的逐字副本。

**根因**：系统提示要求模型只输出 `{"reply": …}` JSON，但历史里存的 assistant 轮次是抽取后的**纯文本**。模型看到「必须输出 JSON」和「自己上一条不是 JSON」的矛盾，4B 模型选择最省力的路径——照抄上一条。

**修复分两步**：

1. 历史里的 assistant 轮次改成 JSON 形式 `{"reply": final}`，与该轮请求的 schema 同形。固定样本下复读率从 33% 降到 4%。
2. 后来换一组互不相关的问题实测，复读率仍是 80%，说明 4% 只是特定样本的巧合。于是不再依赖提示词或采样，加**确定性守卫**：检测到回复与上一条 assistant 逐字相同、且用户没有重复问同一句时，清掉已上屏内容，丢掉历史重问一次；若仍相同，改为「这个问题我暂时答不上来～换个问法试试？」，且这一轮不写历史。

**验证**：真实 `Controller.handle` 路径复现原 80% 场景，守卫后 0/5 重复；`test-llm.js` 覆盖「照抄→重问」「两次照抄→友好提示」「用户重复问同一句→不触发」等分支。

**详见**：[开发记录 十五](desktop-pet-开发记录.md#十五多轮闲聊复读一个被误诊过的-bug)、[十六](desktop-pet-开发记录.md#十六模型缺失连不上答不上来把为什么不行说清楚)

### 7. 模型没安装却被判成「已连接」【开发者：】

**现象**：Ollama 正常运行但 `cfg.model` 没 pull 时，每条消息仍照发，等十几秒后收到 404，界面提示里只有端点和 HTTP 状态码；宠物还说「没太听懂你想做什么」，把责任推给用户措辞。

**根因**：`recheck()` 只看 `/api/tags` 是否可达，不检查返回的模型清单里有没有目标模型，于是状态判成 `ok`。后果不只是文案难看，而是每条消息都白跑一趟网络。

**修复**：

- 状态机新增 `missing`（端点通、模型不在清单里）；`canRoute()` / `ensureReady()` 排除该状态，不再发请求；
- 请求中途收到 404/405 也会 `degrade()` 到 `missing`，防止模型在两次探活之间被删掉；
- 状态变化时重新武装提示（`_noted = false`），从「没装」变成「连不上」会重新提示；
- `applyConfig` 把 `missing` 也算作需要重探的状态，用户 `ollama pull` 后点保存即可恢复；
- 聊天窗只说人话：`missing` 给「运行 `ollama pull xxx`，再点重新检测」并列出已安装模型；`unreachable` 提示确认 Ollama 已启动；端点 URL 和状态码移回设置面板。

**验证**：`test-llm.js` 覆盖 missing / tags 404 / 恢复配置 / 徽章文案；在线测试新增假模型名、坏端口、恢复配置三组；真实路径三场景重跑符合预期。

**详见**：[开发记录 十六](desktop-pet-开发记录.md#十六模型缺失连不上答不上来把为什么不行说清楚)

### 8. 非 Ollama 兼容端点被误判为「未连接」【自查】

**现象**：某些兼容 Ollama 协议的服务只提供 `/api/chat`，没有 `/api/tags`，过去直接判成连不上。

**修复**：`/api/tags` 返回 404/405 视为「端点没有这个接口」，状态仍为 `ok`，跳过模型存在性检查，徽章显示「已连接（读不到模型列表）」；其余非 2xx 仍按失败处理。

**验证**：`test-llm.js` 新增 tags 404 用例。

**详见**：[开发记录 十六](desktop-pet-开发记录.md#十六模型缺失连不上答不上来把为什么不行说清楚)

### 9. 查询噪声词顺序导致事项名被切坏【自查】

**现象（开发期）**：「英语课什么时候」提取出的标题片段是「英语课时候」，匹配不到任何任务。

**根因**：`QUERY_NOISE` 正则里 `什么` 排在 `什么时候` 前面。正则交替从左到右取第一个能匹配的项，短词先命中，长词就被切开。

**修复**：把 `什么时候|啥时候` 提到 `什么` 前面，长词优先。

**验证**：`tests/test-query.js` 的「英语课什么时候」解析与结果断言。

**详见**：[开发记录 十七](desktop-pet-开发记录.md#十七查询增强与画中画计划栏)

### 10. 「下一项 / 还有多久 / 指定事项」只查今天【自查】

**现象（开发期）**：晚上 22:00 问「下一项安排是什么」答「没有了」；「英语课什么时候」漏掉明天的课。

**根因**：查询池固定为 `tasksOfDate(baseDate)`，没有跨天搜索。

**修复**：`titleFrag` / `next` / `askEta` 三类查询改为在「今天及以后」的全库里找；显式指定日期时仍只查那一天。普通清单查询保持不变。

**验证**：`test-query.js` 覆盖跨天事项、跨天下一项、显式日期不外溢。

**详见**：[开发记录 十七](desktop-pet-开发记录.md#十七查询增强与画中画计划栏)

### 11. 画中画计划栏不会随时间刷新【自查】

**现象（开发期）**：计划栏只在打开窗口时渲染一次，「进行中」高亮和已经过去的任务会一直停在旧状态。

**根因**：渲染只绑了 `schedule:changed` 和 `state:change` 两个事件，而时间流逝本身不会触发事件。

**修复**：增加 30 秒定时刷新；关闭画中画时解绑两个总线监听、清掉定时器、移除面板节点，防止窗口关闭后留下监听。

**验证**：`test-pip.js` 50 条，覆盖事件刷新、定时刷新、关闭清理、空状态与 5 行上限。

**详见**：[开发记录 十七](desktop-pet-开发记录.md#十七查询增强与画中画计划栏)

### 12. 形象切换时 `?novideo=1` 被忽略【自查】

**现象（开发期）**：带 `?novideo=1` 强制 SVG 时，切换形象包后角色又变成了视频。

**根因**：`Animation.preload(forceSvg)` 从未把参数写进 `this.forced`，而 `setCharacter()` 判断是否进入视频模式时依赖这个字段。这是改动前就存在的字段从未赋值问题，形象包功能把它暴露了出来。

**修复**：`preload()` 首行补 `this.forced = !!forceSvg;`。同时给 `_probe()` 加序号令牌和 `_probeStop()`，避免切换形象后旧探针的回调回来覆盖新状态。

**验证**：`tests/test-character-pack.js` 覆盖 `forced=true` 不进视频模式、探针竞态清理。

## 二、测试与文档缺陷

### 13. `soft()` 断言把复读 bug 藏了起来【自查】

**问题**：在线测试里「复读次数 ≤ 1」的断言写成 `soft()`，只打印警告、不影响退出码，等于永远不判失败。残余复读因此长期没被发现。

**修复**：确定性的行为（状态机、文案、复读）改用 `check()` 硬断言，现在是 `dups === 0`；`soft()` 只留给「模型措辞好坏」这类主观判断。

**详见**：[开发记录 十六](desktop-pet-开发记录.md#十六模型缺失连不上答不上来把为什么不行说清楚)

**修复**：样本缺失时跳过依赖它的测试组，并明确打印「跳过了什么」；样本存在时行为不变。

## 三、体验优化

### 1. 查询能力增强【开发者：】

- **时间窗口**：`12:00后`、`12点前`、`14:00到16:00`、`明天下午`、`接下来`；支持全角冒号与 `到/至/~/～/-/—` 分隔符。
- **指定事项**：「英语课什么时候」跨天搜索，结果带日期标签，跨天任务写「次日」。
- **还有多久 / 下一项**：「英语课还有多久」区分进行中与未来；「下一项安排」今天没有就跨到明天；剩余时长格式化成「2 天 3 小时」。
- **时段重叠**：上午/中午、下午/傍晚刻意重叠，按口语习惯各查各的，不硬切边界。
- **相交过滤**：`11:00–12:00` 的任务在查「11:30 后」时仍会出现，因为用户问的是「之后还有什么」。
- **模型上下文**：系统提示里的日程从两天扩到三天，模型也支持 `after / before / title / next / eta` 字段；正则能接住的句子仍优先走正则。

**验证**：新增 `tests/test-query.js` 44 条断言，覆盖解析、意图不误伤、窗口过滤、跨天、只读性。

**详见**：[开发记录 十七](desktop-pet-开发记录.md#十七查询增强与画中画计划栏)

### 2. 画中画计划栏【开发者：】

- 角色画中画小窗底部增加今起三天的计划栏：最多 5 行、今日计数、进行中高亮、明天/后天前缀、空状态文案。
- 布局改为 flex 纵向排列，开窗高度额外预留 120px；计划栏最多占 46%。
- 三个刷新时机：日程变更、状态机切换、30 秒定时器。
- 所有节点用 `textContent` 构建，不拼 HTML，避免任务标题注入。
- 受浏览器 API 限制，同时只能有一个画中画窗口，所以计划栏只能塞进角色所在的同一个窗口；窗口位置由浏览器决定，首次需手动拖到右上角。

**验证**：`test-pip.js` 50 条；尺寸、内容、刷新、清理、空状态均有断言。

### 3. 虚拟形象包（应用内换装）【开发者：】

- 顶部新增「更换形象」：支持导入 zip 形象包、点选切换、导出当前形象、删除形象包。

## 五、已知遗留

这些不是「忘了修」，而是当前方案下有意保留或有明确边界的项：

1. **「你好」仍会带上当前时间**（如「你好！现在是…20:30」）。提示词已不再主动汇报任务，但时间仍会带出；对日程宠物来说未必是缺点，没有继续调提示词。
2. **约 6% 的跑题残余**：不是逐字复读，守卫抓不到。要机器化就得给每题配期望关键词，而模型措辞自由度太大，容易误判，所以只记录、不写脆弱断言。
3. **「明晚8点到9点学习英语1小时」**：区间与时长同时写时区间优先生效，但「1小时」不会从标题里剥掉。属于冗余输入，未处理。
4. **画中画位置由浏览器决定**：没有 API 能固定到右上角，首次需手动拖动，Chrome / Edge 一般会记住位置。
5. **内置形象不能导出**：浏览器读不了 `videos/` 目录，内置形象的 zip 需要用 `char_pack.py pack` 生成；面板里的导出按钮在内置形象下禁用并提示。
6. **真机测试不在 `npm test` 里**：`test:e2e` 需要 Edge 与 CDP，`test:live` 需要本地 Ollama；两者是单独命令，避免日常回归被环境卡住。

## 六、可复用的维护经验

- **正则交替长词优先**：`什么|什么时候` 会先切掉 `什么`，导致 `英语课什么时候` 变成 `英语课时候`。同类问题在 `QUERY_NOISE`、状态名归一里都要注意。
- **时间窗口按相交判断**：问「12:00 后」时，跨越 12:00 的任务应该出现；只比开始时间会漏。
- **不确定的跨天语义宁可保持原样**：继承时段前缀只在「继承后晚于起点」时采纳，把判断交给已有的跨天逻辑，而不是猜。
- **先隔离模型，再怀疑代码**：把同样的 payload 直接打给模型，能快速排除「模型噪声」这种错误归因；样本太少 + 没有对照组 = 猜。
- **确定性的东西用硬断言**：`soft()` 只适合主观判断，否则 bug 会被警告淹没。
- **提示有没有，和提示有没有用是两件事**：先跑真实路径看用户到底看到什么，再决定改文案还是改状态机。
- **临时产物与可再生成资源不进仓库**：但删除前先确认没有代码引用、且能从源素材重建。
- **批量语义必须有明确的范围词**：只凭「周一」就推断「全部周一」会抢走单条修改的语义；
  让 `都 / 所有 / 全部 / 每 / 各` 当开关，用户想批量时自然会带上。
- **星期换算别混用两套下标**：JS `getDay()` 是周日=0，周一锚定的下标是周一=0；
  换星期时用 `(target + 6) % 7` 统一到同一套，否则周一会被移到周三。
