# 桌面虚拟宠物日程助手 V2.0 — 使用说明

一个跑在浏览器里的桌面宠物：**它按你的日程表自动切换状态，任务开始时提醒你、任务进行中陪着你、任务结束为你庆祝，任务期间你想摸鱼还会被它拦下来。**

纯前端实现，无需安装、无需服务器、无需联网。

## 一、快速开始

**双击 `desktop-pet/index.html` 即可。**

建议用 Chrome 或 Edge。第一次打开是空闲状态，角色站在画面中央，右下角对话框会跟你打招呼：
没排日程时说「你好呀～我是你的桌面日程小助手……」，已经有日程时会改成「欢迎回来～今天还有 N 项安排」。

想直接看完整效果，打开 `index.html?demo=1`，会自动灌入几条演示日程（含一条"正在进行中"的任务），宠物立刻进入工作/学习状态。

> **如果看到的是橙色小猫而不是紫发角色**，说明视频素材没加载上、自动降级到了内置 SVG 动画。功能完全不受影响，六个状态一样能切换。原因和解决办法见 [第十二节](#为什么我看到的是一只橙色小猫)。

> **想在手机或平板上用？** 见 [第十六节](#十六移动端使用)。

## 三、添加日程

### 方式一：直接跟它说（最快）

在底部输入框打一句中文，回车发送：

```
明天下午两点半上英语课
晚上七点有个会议
后天9点到11点数学复习
明天下午2点到4点开会
```

它会回一句确认（"已添加「英语课」……"），右侧计划表立刻出现这一条。

### 方式二：批量导入安排表（课表 PDF / 模板 PDF / CSV）

除了自己填模板，**教务系统导出的课表 PDF 可以直接导入**：选完文件它自己认出版面，
把「星期一 3-4 节，第 1-9 周」这类信息展开成一条条具体日程，不用手抄。

1. 点顶栏 **「下载模板」**，得到 `schedule_template.pdf`；或者直接用你教务系统导出的课表 PDF
2. 用 WPS / Adobe / 浏览器 打开模板 PDF，直接在表格里填（PDF 里的说明文字导入时自动忽略）
3. 点 **「导入安排表」** 选中文件（课表 PDF、模板 PDF、`.csv` 都行，格式见第四章）
4. 弹窗告知解析到多少条、有多少错误，然后回复：

   | 回复 | 效果 |
   | --- | --- |
   | `确认`（或 `是` / `对` / `好` / `导入`） | **合并**导入，和现有日程并到一起 |
   | `替换` | **清空现有日程**后再导入，只保留文件里的 |
   | `取消` | 放弃本次导入 |

重复的条目会自动跳过，不会产生两份。

#### 直接导入教务系统的课表 PDF

选完文件直接出结果，不用回答任何问题。弹窗里会说明：

```
识别为课表：23 门课。学期第 1 周按 2026-08-31（周一，按课表打印日期推断）计算；
如果不对，直接回复正确的第 1 周周一日期（YYYY-MM-DD），我会重新算。
```

- **学期第 1 周周一是推断的**（课表 PDF 里通常没有这个信息）：优先用你上次回复过的日期，
  没有就按课表里的「打印时间」往回推。**推断值不对就回复一个日期**，它当场重算并记住，
  之后导入同校其它课表不用再说。日期只会整体平移，课程和时间不受影响。
- **课程名后面自动带上教室**（如 `软件测试与管理 H4-413`），地点从课表里读，方便直接看。
- 已经上过的课自动跳过；单双周、跨页的课表都能认。
- 只认「星期 × 节次」这种网格课表。如果你教务系统的版面不一样，会明确提示解析失败，不会静默丢课。

> 「替换」会删掉你现在所有的日程，用之前想清楚。误操作的话只能用「导出备份」的文件救回来。

### 方式三：周期日程

安排表的 `date` 列可以直接写规则词，导入时自动展开成具体日期，窗口是**今天起往后数 14 天**（今天是第 0 天，所以一共覆盖 15 个日期）：

```
工作日,09:30,11:30,写代码,working      ← 展开成这个窗口里所有工作日
每天,22:30,23:00,睡前复盘              ← 每天一条（category 留空会自动归类）
周三,14:00,15:30,英语精读              ← 每周三一条
```

> 窗口长度是 `App.Config.materializeDays`（默认 14）。窗口外的规则不会提前生成，
> 但**只要导入时用了规则词，之后每天打开页面都会自动往后补**，不需要重新导入。

## 四、导入格式参考

**PDF 模板**：模板就是一张五列表格（`date,start,end,title,category`），填好后直接导入。应用内部会把
PDF 表格按列位置还原成 CSV，再走同一套解析与校验，所以下面列的规则、规则词、`#` 注释对两者完全一致。

要用 PDF 导入，注意三点：

- 必须是**文字型 PDF**（文字可以选中复制）。扫描件、图片型 PDF 没有文字层，提不出内容，会提示导入失败
- 用模板改，**不要改动列的位置**；每个单元格保持单行，不要手动换行
- 表格之外的文字（模板顶部的说明、页脚）会被自动忽略，不会变成日程；但**别在表格外随手写数据**
- 不限于本模板：自己做的五列表格（表头文字一致）另存/打印成 PDF 也能导入，不挑生成工具

改不了 PDF 也没关系：**CSV 一样能导入**，格式如下。

### 课表 PDF（教务系统导出）

不是五列表格也没关系 —— 教务系统那套「星期 × 节次」的网格课表能直接认出来，见第三章方式二。
这类 PDF 常见两个坑，应用都已经处理：

- **文字提不出来**：很多课表用未内嵌的中文字体，字形到文字的对照表放在 PDF 外面。
  应用内置了 GB 系 CMap（`lib/pdfjs/cmaps.js`，简体中文），双击打开也能解析
- **版面是转 90° 的**：节次沿横向铺开、跨页成一列，星期沿纵向排 7 行，每个格子里的
  文字是竖着写的多行。识别逻辑按坐标还原，不靠「看起来像表格」

用到的信息：`(3-4节)1-9周(单)` → 节次对应的时间、周数范围、单双周。
`场地:H4-413（江）` → 房间号（校区后缀去掉）拼到课程名后面。其余元数据（教师、教学班、
学分等）会读完但不进日程，避免标题太长。

### CSV 格式

表头固定为 `date,start,end,title,category`（顺序不能变）：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| `date` | ✅ | `YYYY-MM-DD` 具体日期；或规则词 `每天` / `工作日` / `周末` / `周一`~`周日` |
| `start` | ✅ | 24 小时制 `HH:MM` |
| `end` | ❌ | 留空默认 60 分钟；跨天写 `00:30(+1)` |
| `title` | ✅ | 任务名称。CSV 里含逗号**要用双引号包起来**；PDF 里按列边界切分，怎么写都行 |
| `category` | ❌ | `studying` / `working` / `general`，也可写中文 `学习` / `工作` / `通用`；留空则按标题关键词自动判断 |

**一个完整的例子：**

```csv
date,start,end,title,category
# 以 # 开头的行是注释，不会被导入
2026-09-21,09:00,10:30,英语听力训练,studying
2026-09-25,19:00,20:00,项目周会,working
2026-09-26,23:00,00:30(+1),夜间实验收尾,working
工作日,08:30,09:00,晨读背诵,studying
每天,12:10,12:50,午休,general
周一,14:00,15:30,高等数学复习,
周末,10:00,11:30,兴趣手绘,
```

支持的细节：UTF-8 BOM、双引号转义、字段内换行、`#` 注释行、空行跳过。表头写错会整份拒绝并说明原因；单行时间格式错误只跳过该行，其余正常导入。PDF 导入复用同一套校验与规则词展开，报错里的行号对应重建出来的表格行。

**会被跳过的行**（导入时会逐条列出来）：

- `title` 超过 40 个字
- `date` 是**已经过去的日期**——过去的日程排了也没意义，直接忽略
- 和前面某行完全重复的条目

另外 `每天` 还有一个等价写法 `每日`，两个都认。

## 五、对话指令参考

### 新增

| 你可以说 | 效果 |
| --- | --- |
| `明天下午两点半上英语课` | 明天 14:30-15:30 英语课，归类"学习" |
| `晚上七点有个会议` | 今天 19:00-20:00 会议，归类"工作" |
| `后天9点到11点数学复习` | 后天 09:00-11:00 数学复习 |
| `明天下午2点到4点开会` | 明天 14:00-16:00 开会（**终点自动继承起点的"下午"**） |
| `晚8点到9点学习英语` | 今天 20:00-21:00 学习英语（`晚` 单字＝晚上，不会当成早上 8 点） |
| `明晚8点到9点学习英语` | 明天 20:00-21:00 学习英语 |
| `一个半小时的阅读安排在下午三点` | 今天 15:00-16:30 阅读（**时长表达**） |

### 删除

| 你可以说 | 效果 |
| --- | --- |
| `取消明天的英语课` | 按标题+日期匹配删除 |
| `把三点的会议删掉` | 按时间+标题匹配删除 |

匹配到多条时会列出候选，回复序号即可：`找到多条安排，回复序号告诉我删除哪一个：`

### 修改

| 你可以说 | 效果 |
| --- | --- |
| `把下午三点的会议改成四点` | 时间改成 16:00（**自动继承"下午"时段**，不会变成凌晨 4 点） |
| `英语课挪到周五` | 改日期，**时长保持不变** |

### 查询

| 你可以说 | 效果 |
| --- | --- |
| `今天还有什么安排` | 列出今天剩余日程，并在右侧计划表高亮 |
| `明天有什么` | 列出明天的日程 |

### 复制整天（把某天的安排整批搬到另一天）

| 你可以说 | 效果 |
| --- | --- |
| `把明天的安排复制到周五` | 明天**全部未完成**的安排各复制一份到周五，**源日原样保留** |
| `把9月20日的安排复制到9月25日` | 同上，用具体日期 |
| `把周二的安排拷贝到周三` | `拷贝` 同义 |
| `把明天的安排抄到后天` | `抄到` 同义（但 `抄作业` 不会被误判） |
| `把安排复制到周五` | 左边不写日期 = **今天** |

只做**整天**搬运。左边写了名字或时间（如 `把明天下午三点的会议复制到周五`）会被拦住并提示改写；想搬单条请用上面的 `挪到` / `改到`。

源日**已经完成**的安排不复制，跳过了几条会一并告诉你。

#### 时间撞上了怎么办

目标日已有安排和要复制过去的时间重合时，会把**撞上的两条放在同一个框里**逐对列出来，一次问完：

> 把明天的 3 项安排复制到周五（另有 1 项已完成，不复制），其中 1 对时间撞上了：
> - 要复制 **英语课** 09:00–10:00 ／ 已有 **晨读** 09:30–10:30
>
> 回复「重叠」撞上的两条都留下，回复「更换」把撞上的合并成一条（名字用逗号连起来，如「英语课,晨读」），回复「取消」放弃。

| 回复 | 效果 |
| --- | --- |
| `重叠`（`都留` / `保留` 也行） | 撞上的两条**都留下**，各占各的时间 |
| `更换`（`替换` / `合并` 也行） | 撞上的两条**合并成一条** |
| `取消` | 什么都不动，两边都保持原样 |

**「更换」具体怎么合**：名字用逗号接起来，时间段取**并集** —— 先开始的那个的头时间，到最后一个结束的那个的尾时间。

| 要复制的 | 目标日已有 | 合并结果 |
| --- | --- | --- |
| `英语课` 09:00–10:00 | `晨读` 09:30–10:30 | `英语课,晨读` **09:00–10:30** |
| `实验课` 10:00–11:00 | `答疑` 09:45–10:30 + `自习` 10:30–11:15 | `实验课,答疑,自习` **09:45–11:15** |

没撞上的安排照原样复制过去。一条已有安排同时被多条撞上时，只并进**开始最早**的那条。

复制出来的副本是**独立的一次安排**，不再带原来的周期规则 —— 源日是个「每天」的安排，复制到某一天也只有那一天多一条，不会跟着天天长。

> 撞车只比**目标日当天**。跨天任务（如 23:00–01:00）落过去时，次日凌晨那半段不会去和次日的安排比对，这点和「新增」的重叠检查范围一致。

### 时间表达的完整支持

- **日期**：今天 / 今日 / 今儿 / 明天 / 明日 / 后天 / 大后天 / **今晚 / 明晚 / 后晚** / 周一~周日 / 这周五 / 下周三 / `2026-09-21` / `9月21号`
- **时段**：上午 / 早上 / 早晨 / 清晨 / 中午 / 下午 / 傍晚 / 晚上 / 夜里 / 凌晨 / **晚**（单字也算，`晚8点` = `晚上8点`）
- **时间**：`三点` `三点半` `三点一刻` `三点三刻` `三点二十` `15:30` `15点30分`；中文数字 `十点` `十一点` `十二点` 都认
- **区间**：`下午2点到4点` `下午2点至5点` `晚上7点~9点`。**终点没写时段时会继承起点的**，所以「下午2点到4点」是 14:00–16:00 而不是跨天到凌晨 4 点
- **特殊**：`下午十二点` → 12:00；`晚上十二点` → 次日 00:00；`晚上10点到2点` → 22:00 到**次日** 02:00（终点明显早于起点时按跨天理解）

### 听不懂的时候

它不会瞎猜。解析不了会如实说明并给例子：

| 回复 | 含义 |
| --- | --- |
| `没太听懂你想做什么～可以说「添加」「删除」「修改」「查询」「复制」相关的话。` | 没识别出意图 |
| `要安排在几点呢？` | 识别出要新增，但没说时间 |
| `这件事叫什么名字呢？` | 识别出要新增，但没说做什么 |
| `没听清是哪一天，可以说明「今天」「明天」或具体日期。` | 日期有歧义 |
| `要复制到哪一天呢？说「把明天的安排复制到周五」这样就行。` | 说了「复制」但没给目标日 |
| `复制整天是把那一天的全部安排都搬过去，名字和时间不用写哦～` | 复制语句里带了名字/时间（只支持整天） |

### 重叠与确认

新增的时间如果和已有安排重叠，会先问一句：

> 这个时间和「项目周会」重叠了，确定要添加吗？（回复「确认」或「取消」）

回复 `确认` / `确定` / `是` / `对` / `好` / `好的` / `嗯` / `y` / `yes` / `继续` / `添加` 都算同意；回复 `取消` / `算了` / `不要` / `不用` / `否` / `n` / `no` 放弃。

## 六、角色状态说明

### 两套形象，自动选

| 模式 | 长什么样 | 怎么触发 |
| --- | --- | --- |
| `video` | 紫发少女（默认素材） | `videos/` 下有能播的视频素材 |
| `svg` | 橙色小猫 + CSS 动画 | 视频素材缺失、加载失败，或加了 `?novideo=1` |

启动时会试播 `videos/idle.webm`（超时 5 秒），能播就用视频，否则自动降级到内置 SVG 小猫，
不需要手动切换。当前用的是哪套，按 `F12` 在控制台输入：

```js
document.getElementById('stage').dataset.mode      // 'video' 或 'svg'
document.getElementById('stage').dataset.state     // 当前状态，如 'studying'
```

### 七种状态

**全部由系统本地时间 + 你的日程表现场推导**，不需要你手动切换。分基础态和临时态两类：

**基础态**（循环播放，直到任务状态变化）：

| 状态 | 徽章 | 触发条件 | 角色表现 | 素材文件 |
| --- | --- | --- | --- | --- |
| `idle` | 空闲中 | 当前没有进行中的任务 | 站立、轻微呼吸摆动 | `idle.webm` |
| `studying` | 学习中 | 正在进行「学习」类任务 | 坐在书桌前敲键盘 | `studying.webm` |
| `working` | 工作中 | 正在进行「工作」/「通用」类任务 | 同上（书桌场景） | `working.webm` |

**临时态**（播完一轮回到基础态）：

| 状态 | 徽章 | 触发条件 | 角色表现 | 素材文件 | 时长 |
| --- | --- | --- | --- | --- | --- |
| `alert` | 提醒 | 任务**刚开始**的 90 秒内 | 举手挥动 + 感叹号 + 气泡播报 | `alert.webm` | 5 秒 |
| `done` | 任务完成 | 任务**刚结束**时 | 闭眼笑 + 飘心 + 完成播报 | `done.webm` | 3.5 秒 |
| `refuse` | 温馨提醒 | 任务进行中你提出娱乐请求 | 抖动 + 红光 + 拒绝话术 | `refuse.webm` | 2.5 秒 |
| `talking` | 交流中 | 本地模型正在理解 / 组织回复 | 说话、讲解手势 | `talking.webm` | 循环到回复结束 |

> `talking` 只在**开启本地大模型**（[第十八节](#十八本地大模型ollama)）后才会出现，且是唯一**循环播放**的临时态：
> 回复要几秒就循环几秒，由回复返回时主动收掉，默认 90 秒只是兜底上限。开关关着时它永远不会出现。

**另外两个提醒态**：`warnStart`（开始前 5 分钟提醒）和 `warnEnd`（结束前 10 分钟打气）。
它们**不占独立素材**，直接复用 `alert` / `done` 的视频，只把徽章文字换成「提醒」和「加油」。

**一个重要的设计**：状态不是"事件推送"而是"**每一秒从当前时间和日程重新算一遍**"。所以合上笔记本两小时再打开、系统休眠、手动改系统时间、跨过午夜——它都能自己算对，不会因为漏掉某个事件就卡在错误状态。

**重新打开页面不会重播提醒**。比如任务 14:00 开始，你 14:30 才打开页面，它会直接进入"学习中"，而不是弹一次"到时间了"。

> 想换成自己的角色形象？见 [第十七节](#十七虚拟形象自定义)。

## 七、跨状态拒绝

这是这个项目最有意思的机制。**任务进行中**，你如果想摸鱼：

```
你：我想玩游戏
宠物：现在是学习时间哦，专心完成任务再玩吧～     ← 抖动 + 红光
```

- **不会打断日程**——拒绝动画播完自动回到任务状态
- **不会写入日程表**——娱乐请求根本不会入库
- **再说一次会更严厉**：

  ```
  你：那我看个视频
  宠物：不行哦！英语听力训练还没结束呢，娱乐的事等完成了再说！
  ```

- **空闲时间提娱乐**：不会拒绝，只会安抚一句"现在是空闲时间，想放松就玩一会儿吧～不过到了任务时间我会提醒你的。"
- **带具体时间的娱乐安排**（比如"周五晚上八点看电影"）算正常日程，照常入库，不会被拒绝。
  入库时**类别会归成「通用」**——娱乐不单独占一种角色动画，宠物到点显示的是工作状态

### 怎么判定"这是娱乐请求"

不用一字不差地说关键词——**整句话里只要出现娱乐词就算**，前后加多少字都行：

| 说法 | 命中 |
| --- | --- |
| 我想玩游戏 | ✅ 句子里含「玩游戏」 |
| 现在好想打游戏啊 | ✅ 含「打游戏」 |
| 我想玩一会儿游戏 | ✅ 动词和宾语被隔开，靠宽松匹配兜住 |
| 看个视频放松下 | ✅ |
| 帮我整理追剧片单 | ⚠️ 也会被判成娱乐（句子里有「追剧」），属于误伤，换个说法即可 |
| 明天下午三点整理游戏攻略 | ❌ 不算——「玩游戏」这个词被拆开了，且带了具体时间，按普通日程入库 |

**判定分两步**：

1. **精确子串**：句子里含 `玩游戏 / 打游戏 / 看视频 / 刷短视频 / 刷手机 / 追剧 / 刷剧 / 看电影 / 看动漫 / 睡觉 / 躺会 / 摸鱼 / 打盹` 任意一个
2. **宽松匹配**：动词和宾语之间最多隔 4 个字也算，覆盖「玩一会儿游戏」「看个视频」「刷会儿手机」这类口语说法

改这两组词在 [app.js](../desktop-pet/app.js) 的 `App.Config.keywords.entertainment` 和 `App.Config.entertainmentPatterns`。想加"打牌""逛街"之类，往第一个数组里加就行。

> 注意：拒绝只在**任务进行中**才触发（见本节开头）。空闲时同一个句子只会得到安抚，不是没识别出来。

## 八、提醒机制

除了任务开始/结束的准点播报，还有两个**提前提醒**（默认开启，无需设置）：

| 时机 | 说什么 | 角色表现 |
| --- | --- | --- |
| 任务**开始前 5 分钟** | 「×××」还有 5 分钟就要开始了，准备一下哦～ | 举手挥动（复用提醒动画） |
| 任务**结束前 10 分钟** | 「×××」还有 10 分钟就结束啦，坚持住，胜利在望～ | 闭眼笑（复用完成动画） |

细节：

- **结束前打气只针对当前正在进行的那个任务**，不会被重叠的其他安排反复打扰
- **每条只播一次**，不会每分钟重复
- **迟到补报**：如果打开页面时已经进入提醒窗口（比如任务 14:00 开始，你 13:57 才开页面），会立刻补播一次
- **跨午夜的任务也能正确处理**，不会因为日期翻转而漏播或重播
- 提前量可以调：改 `app.js` 里 `App.Config` 的 `warnStartMin` / `warnEndMin`（见第十二节）

## 十、界面外观：舞台背景与界面壁纸

这是两个不同的东西，作用范围不一样，可以同时用：

| | 舞台背景 | 界面壁纸 |
| --- | --- | --- |
| 按钮 | 更换背景 | 界面壁纸 |
| 作用范围 | 只铺在宠物舞台那块 | 铺满整个窗口，像电脑桌面壁纸 |
| 预设 | 1 张（紫色，放 `data/backgrounds/`） | 1 张（中山装·人生哲理，放 `data/wallpapers/`） |
| 能导入本地图片 | ❌ | ✅ |

> 两者的图片**分开放**：舞台背景在 `data/backgrounds/`，界面壁纸在 `data/wallpapers/`。
> 换壁纸的面板里只会列出 `data/wallpapers/` 下的图，不会混进背景图。

### 舞台背景

点 **「更换背景」**，展开一排缩略图，点一张就换上了；点「无」恢复纯色。也可以点顶栏的 **「清除背景」**。

### 界面壁纸

点 **「界面壁纸」**：

- 点预设缩略图直接换
- 点 **「本地图片…」** 选自己电脑上的图，会自动处理（等比压到最长边不超过 1920 像素，转成体积更小的 JPEG），原图不动
- 点「无」恢复纯色，或点 **「清除壁纸」**

**换上壁纸后，界面上的面板会变成半透明**，让壁纸透出来——像桌面壁纸那样。顶部日期栏保持不透明，避免滚动时日程文字和壁纸糊在一起。

> 壁纸图片建议选**偏暗、色调统一**的，文字会更好读。压暗程度是可调常量，觉得太暗或太亮见第十二节常见问题。

### 这两项设置存在哪

单独存在 `desktop_pet_settings` 这个 LocalStorage 键里，**不掺进日程数据**。清除背景/壁纸不影响你的日程。

**注意**：「导出备份」只备份日程，**不包含背景和壁纸设置**。换设备后需要重新选一次。

点顶栏 **「画中画」**，宠物舞台会被搬进一个独立的悬浮小窗，可以拖到屏幕任意角落、置顶在其他窗口之上，主窗口该干嘛干嘛。

## 十二、常见问题

### 为什么我看到的是一只橙色小猫？

小猫是**内置的降级动画**。当 `videos/` 里的视频素材加载失败时，项目会自动切到它，保证功能可用。

按 `F12` 打开控制台可以看到具体原因：

| 控制台提示 | 含义 | 处理 |
| --- | --- | --- |
| `[Animation] 已启用视频素材 videos/*.webm` | 一切正常 | — |
| `[Animation] videos/idle.webm 加载偏慢…` | 读盘慢，先降级，加载好会自动切回 | 稍等即可 |
| `[Animation] 缺少 videos/xxx.webm，暂用 idle 素材代替` | 个别状态素材缺失 | 补上对应文件 |
| `[Animation] 未找到可用视频素材，已启用内置 SVG 角色动画` | 素材全都没加载上 | 见下 |

**排查顺序：**

1. **先按 `Ctrl+F5` 强制刷新**——如果你在素材生成之前就打开过页面，看到的是旧状态。
2. 确认 `desktop-pet/videos/` 目录下确实有 7 个 `.webm` 文件（打开文件夹看一眼）。
3. **确认你是在浏览器里打开的，不是 IDE 的预览窗口**。IDE 预览不是真正的 `file://` 页面，读不到同级的 `videos/` 目录，必然降级成猫。
4. 想强制对比两种效果：加参数 `index.html?novideo=1` 会主动使用小猫。

更详细的原因和换装方法见 [第十七节](#十七虚拟形象自定义)。

### 数据存在哪里？会不会丢？

存在浏览器的 LocalStorage 里：

| 键名 | 存什么 |
| --- | --- |
| `desktop_pet_v2` | 你的日程数据 |
| `desktop_pet_settings` | 舞台背景、界面壁纸的选择，以及本地模型的开关/地址/模型名 |

关掉浏览器不会丢。**但清浏览器数据会丢**，所以建议定期点 **「导出备份」** 存一份 JSON。需要时点 **「导入备份」** 选回那个文件即可。

另外数据损坏时不会白屏：无法解析的内容会被自动备份到 `desktop_pet_v2_broken_<时间戳>`，然后以空列表启动。
数据版本比当前程序**更新**时（比如你用新版打开过、又换回旧版），同样会先备份到 `desktop_pet_v2_future_<时间戳>` 再启动，不会直接覆盖掉。

### 跨天的任务怎么填？

`end` 写成 `00:30(+1)` 表示次日凌晨 0:30 结束。计划表里会显示成 `23:00 - 次日 00:30`。

### 换了台电脑 / 换了浏览器，日程还在吗？

不在。LocalStorage 是按浏览器隔离的。用「导出备份」→「导入备份」迁移。背景和壁纸设置在备份之外，需要重新选。

### 怎么改"一个任务默认多长时间"之类的设置？

打开 `desktop-pet/app.js`，顶部的 `App.Config`（约 132-178 行）集中了所有可调项：

| 配置 | 当前值 | 作用 |
| --- | --- | --- |
| `defaultDurationMin` | `60` | CSV 里 `end` 留空时的默认时长（分钟） |
| `tickMs` | `1000` | 状态机检查间隔（毫秒） |
| `materializeDays` | `14` | 周期日程向后展开多少天 |
| `keywords` | 见文件 | 按标题自动归类的中文关键词表（`entertainment` 那一组就是娱乐词） |
| `entertainmentPatterns` | 见文件 | 娱乐词的宽松匹配正则，兜住「玩一会儿游戏」这种中间隔字的说法 |
| `refusePhrases` | 见文件 | 两级拒绝话术（含 `{category}` / `{title}` 占位） |
| `stateLabel` | 见文件 | 角色头顶徽章的文字。想改叫法改这里 |
| `stateByCategory` | 见文件 | 任务类别 → 基础态。想让「通用」类任务也显示学习状态，把 `general` 改成 `'studying'` |
| `tempMs` | `{alert:5000, done:3500, refuse:2500, warnStart:5000, warnEnd:4000}` | 各临时态的持续时间 |
| `startWindowSec` | `90` | 任务开始后多久内算"准点提醒" |
| `warnStartMin` | `5` | 任务开始前几分钟提醒 |
| `warnEndMin` | `10` | 任务结束前几分钟打气 |

**壁纸压暗程度**不在 `app.js`，在 `settings.js` 顶部的 `WALLPAPER_OVERLAY` 常量：

```js
var WALLPAPER_OVERLAY = 'linear-gradient(rgba(15,19,34,.35), rgba(15,19,34,.35)), ';
```

那个 `.35` 是压暗层的不透明度——**调小壁纸就更亮，调大变暗**。觉得壁纸不够显眼就往 `.25` 调，觉得刺眼就往 `.45` 调。

舞台背景的压暗层是另一个常量 `OVERLAY`（当前 `.32`），改法一样。

### 界面可以换多大的壁纸？

导入时自动等比缩放到最长边 1920 像素以内、转成 JPEG（质量 0.8）。所以放多大的原图都行，超过 20MB 的文件会被拒绝。处理后的图存在 LocalStorage 里，所以图越大越占空间——建议选压缩后 1MB 以内的。

### 宠物突然不动的？

先看你系统的**「减少动态效果」/「动画效果」**设置。Windows 在「设置 → 辅助功能 → 视觉效果」，macOS 在「系统设置 → 辅助功能 → 显示」。

这个项目会尊重系统的这个开关（`prefers-reduced-motion`）：**打开后所有动画都会被停掉**，宠物就定格了。这是有意为之，不是故障——对晕动症用户来说动画是负担。想恢复动画，把这个系统开关关掉即可。

## 十三、调试与演示参数

在 `index.html` 后面加参数即可，多个用 `&` 连接：

| 参数 | 例子 | 作用 |
| --- | --- | --- |
| `demo=1` | `index.html?demo=1` | 灌入演示日程，立刻看到工作/学习状态 |
| `time` | `index.html?time=14:30` | 假装现在是 14:30，用来演示特定时段的状态 |
| `date` | `index.html?date=2026-09-21` | 假装今天是某一天（配合 `time` 用） |
| `freeze=1` | `index.html?time=14:30&freeze=1` | 冻结时钟，时间停在 `time` 那一刻不再前进。**必须和 `time` 一起写**，单独写不生效 |
| `novideo=1` | `index.html?novideo=1` | 强制使用内置 SVG 小猫动画 |
| `nollm=1` | `index.html?nollm=1` | 本机跑着 Ollama 但想验证**离线路径**：即使开关开着也完全不连模型，待机、加日程、闲聊全部走原来的正则通路 |

**演示时最有用的一招**：先导入一份日程表，然后 `?time=<某个任务开始前一分钟>&freeze=1` 打开，再把 `freeze` 去掉刷新，就能完整看到"提醒 → 任务中 → 完成"的整条链路。

### 控制台里更灵活的调试钩子

浏览器按 F12 打开控制台，可以直接调 `App.debug`——比 URL 参数灵活，**不用刷新页面**：

| 命令 | 作用 |
| --- | --- |
| `App.debug.set('14:30', '2026-09-21')` | 把时钟拨到指定日期时间，当场看状态变化 |
| `App.debug.tick()` | 手动触发一次状态检查 |
| `App.debug.state()` | 打印当前状态快照（基础态、临时态、当前任务） |
| `App.debug.refuse()` | 手动播放一次拒绝动画（不用真的打字） |
| `App.debug.seed()` | 等同于 `?demo=1` 的灌数据 |

改完代码想验一下有没有弄坏东西，一条命令跑完全部 9 个离线套件（463 条断言，纯 Node，几秒出结果、不开浏览器）：

## 十六、移动端使用

### 先说结论：哪些能用，哪些不能

| 功能 | 电脑 | 手机 / 平板 |
| --- | --- | --- |
| 日程管理、对话指令、PDF / CSV 导入 | ✅ | ✅ |
| 课表 PDF 导入（教务系统网格课表） | ✅ | ✅ |
| 宠物动画、六种状态 | ✅ | ✅ |
| 舞台背景、界面壁纸 | ✅ | ✅ |
| 开始前 / 结束前提醒 | ✅ | ✅（页面开着才响） |
| **画中画** | ✅ 桌面 Chrome/Edge 116+、Firefox 151+ | ❌ 不支持 |
| **要不要额外装东西** | 不用，浏览器直接开 | Android **要装 QuickEdit**；iOS 见下文 |

应用本身是纯 HTML/CSS/JS，不需要联网、也不需要安装。但**「用浏览器直接打开」这条路只在电脑上成立**：

- **Windows 平板（Surface 这类）**：和电脑一样，什么都不用装
- **Android**：必须额外装一个 **QuickEdit** 当启动器，光用 Edge / Chrome 打开是用不了功能的（[见下文](#android-手机--平板)）
- **iPad / iPhone**：Files App 里点 HTML 读不到同目录的资源，要另想办法（[见下文](#ipad--iphone)）

**唯一不能用的是画中画**——那是浏览器桌面端专有的 API（`documentPictureInPicture`），Safari 和所有手机浏览器都没有实现（Android 上的 Chrome 也没有）。项目已经做了处理：**不支持时「画中画」按钮自动隐藏**，不会出现点了没反应的情况（[pip.js:38](../desktop-pet/pip.js#L38)）。

### Windows 平板（Surface 这类）

**和电脑完全一样，不需要任何额外步骤。**

1. 把 `desktop-pet` 文件夹拷到平板上
2. 双击 `desktop-pet/index.html`
3. 完成。画中画也能用

### Android 手机 / 平板

**Android 上光有浏览器不够，必须额外装一个 QuickEdit 当启动器。** 它不在应用商店里，**要用 Edge 打开网页搜索并下载安装**。只把 HTML 交给 Edge / Chrome 打开是**用不了功能的**，原因见下面。

1. **把整个 `desktop-pet` 文件夹拷进设备**——不是只拷 index.html，CSS、脚本、视频素材都在子目录里
   - 数据线连电脑直接拖
   - 或者用 U 盘 / 网盘中转
2. **用 Edge 搜索 QuickEdit，下载并安装**（应用商店里没有，走网页下载）
3. 在设备上打开**文件管理器**（系统自带的「文件」App）
4. 找到 `desktop-pet/index.html`，点它
5. 弹出「打开方式」时选 **QuickEdit**——**不要选 Edge / Chrome**
6. 在 QuickEdit 里打开 `index.html`，用它内置的浏览器预览，页面才能完整跑起来

**为什么必须多装这一个 App**：Android 上直接把 HTML 交给 Edge / Chrome 打开时，它们读不到同目录的 CSS、JS 和视频，结果是**页面能显示但没样式、没动画、点哪都没反应**——功能等于没有。QuickEdit 内置了浏览器预览，能按整个文件夹来读，所以功能正常。**这不是项目的问题，是 Android 打开本地 HTML 的通用限制**，换个项目也一样。

**三个坑：**

- **别在微信 / QQ 聊天记录里直接点 HTML 文件**。微信内置的预览器渲染不了完整页面，你会看到一堆源码或空白。必须先把文件存到设备本地，再用文件管理器打开。
- **「打开方式」必须选 QuickEdit**。选了 Chrome / Edge 会看到上面说的那种「能打开但功能全废」的页面，很容易误以为项目坏了。
- **如果点开是空白或只有文字**，说明没读到同目录的 CSS/JS。先检查是不是只拷了 `index.html` 一个文件——整个文件夹都要在；文件夹没问题的话，就是启动器没用 QuickEdit。

**加到主屏幕（像 App 一样打开）**：用 Chrome 打开后，右上角菜单 →「添加到主屏幕」。之后从桌面图标点进去，不用每次翻文件管理器。

> 注意两件事：这样加的是**书签快捷方式**，不是离线 App，文件被移动或删除后图标会失效；而且**这条只在页面能被浏览器正常打开时才有意义**——如果必须靠 QuickEdit 才能跑起来，那就只能每次从文件管理器点进去。

### iPad / iPhone

iOS 比 Android 麻烦：**Files App 里点 HTML 只会预览单个文件**，同目录的 CSS、JS、视频全都读不到，页面会散架。直接拷文件夹这条路走不通，有两个替代方案。

**方案 A：电脑起个本地服务器（推荐，最省事）**

要求：电脑和 iPad 连**同一个 Wi-Fi**，且电脑保持开机。

在 `D:\AIcompete` 目录下打开命令行：

```bash
python -m http.server 8000
```

没装 Python 的话，装了 Node.js 也可以用：

```bash
npx serve
```

**查电脑的局域网 IP**：另开一个命令行窗口，输入 `ipconfig`，找「IPv4 地址」，形如 `192.168.1.5`。

**iPad 上**：Safari 地址栏输入 `http://192.168.1.5:8000/desktop-pet/`（换成你查到的 IP）。

打不开的话，依次排查：

- 先确认电脑上的命令行窗口还开着（关掉窗口 = 服务器关了）
- Windows 防火墙可能拦了，弹窗时选「允许访问」
- 确认两台设备连的是同一个 Wi-Fi（手机热点不算）

**这个方案的缺点**：电脑必须开着，且 iPad 每次都得手动输网址。好处是 iPad 上的数据存在 Safari 里，不会丢。

**方案 B：用支持本地网站的 App**

App Store 里搜 **Koder**（或类似的代码编辑器 App，关键词 "local web server"）。

1. 把 `desktop-pet` 文件夹通过「文件」App 或 iCloud 传进 Koder
2. 在 Koder 里打开 `index.html`，用它内置的浏览器预览

不用电脑配合，但操作比方案 A 繁琐，App 也需要付费或看广告。

**iPhone 同理**：上面两个方案在小屏手机上同样适用。不过**竖屏手机上界面是单列的**，舞台在上、计划表在下，需要上下滚动——能用，但不如平板和电脑舒服。

### 移动端通用注意事项

**布局会自动适配**：屏幕宽度小于 900px 时，界面自动从「左舞台 + 右计划表」的双列切成上下单列（[style.css:693](../desktop-pet/style.css#L693)）。平板横屏（宽度通常 >900px）会保持桌面布局。

**提醒只在页面开着时响**：这跟设备无关，是项目的设计——提醒靠页面内的定时器，**你把浏览器切到后台或锁屏，提醒就不会响**。手机上尤其容易发生（切个微信就没了）。要让它一直提醒，得把页面保持在前台，且关闭系统的省电限制。

**数据不跨设备同步**：日程存在各自浏览器的 LocalStorage 里，按设备、按浏览器隔离。手机上打开是空的，跟电脑上的数据不互通。迁移方法：

1. 电脑上点顶栏 **「导出备份」**，得到一个 JSON 文件
2. 把文件传到手机（微信文件传输助手发给自己就行）
3. 手机上打开应用，点 **「导入备份」** 选那个文件

> 背景和壁纸设置**不包含在备份里**（备份只存日程）。手机上需要重新选一次，导入的本地壁纸图片也得重新导入。

**触摸操作**：界面是按点击设计的，触摸屏上所有按钮都能正常点。输入框会自动弹出中文键盘，和平时打字一样。

## 十七、虚拟形象自定义

宠物的形象有两套（见[第六节](#六角色状态说明)）：**视频素材**（默认）和**内置 SVG 小猫**（降级用）。换形象分三种做法，按改动从小到大排：

| 想做的事 | 要动的东西 | 难度 |
| --- | --- | --- |
| 换成自己画的角色 | 替换 `videos/` 下 7 个视频文件 | 不用改代码 |
| 换个造型 / 改动作 | 改 `character/animation.js` 的 SVG + `style.css` 的动画 | 改代码 |
| 改状态名称 / 时长 / 归类 | 改 `app.js` 的 `App.Config` | 改配置 |

### 换成自己的角色（不用改代码）

1. 准备好 7 段动画，按下面的文件名命名
2. 丢进 `desktop-pet/videos/`，覆盖同名文件
3. `Ctrl+F5` 强制刷新（避免缓存）

| 文件名 | 对应状态 |
| --- | --- |
| `idle.webm` | 空闲 |
| `studying.webm` | 学习中 |
| `working.webm` | 工作中 |
| `alert.webm` | 提醒（任务开始） |
| `done.webm` | 完成（任务结束） |
| `refuse.webm` | 拒绝（任务时段摸鱼） |
| `talking.webm` | 交流中（本地模型思考 / 回答时，见[第十八节](#十八本地大模型ollama)） |

**命名严格区分大小写，必须完全一致。** 文件名不对 = 那个状态找不到素材。

**素材要求：**

- **首选 WebM（VP9 + alpha 通道，`-pix_fmt yuva420p`）**，必须透明背景
- 也支持 `.mp4`，但**必须是 H.264**。实测 HEVC（H.265 / `hvc1`）在 Chrome / Edge 上无法解码，放进去只会触发降级
- 加载顺序：`<状态>.webm` → `<状态>.mp4` → 内置 SVG 小猫，逐级回退。所以少放一两个也不至于崩，缺的那个会用 `idle` 的画面顶替
- **单个文件建议小于 3MB**，本地加载才不会卡
- **尺寸 720×720 正方形最合适**。视频按 `object-fit: contain` 适配舞台，非正方形不会被裁剪，但会留白
- **基础态（idle / studying / working）会循环播放，首尾帧要能自然衔接**
- **临时态（alert / done / refuse）只播一轮**，播完自动回基础态，同时受 `tempMs` 上限约束
- **`talking.webm` 是唯一循环的临时态**，格式要求和其他文件一样。它只服务本地大模型，不做这一个、或者模型开关没开，其他六个状态照样用

> 现有这套素材是 720×720 / 24fps / 5 秒。

### 自己制作一套视频素材（完整流程）

从一段视频到 7 个能用的素材文件，五步。**第三步的抠图脚本是实测过的**——在一张
720×720 合成帧上验过：四角透明、角色主体不透明、**角色内部的纯白块被正确保留**、
边缘有羽化过渡、背景侧没有残留光晕。

#### 准备环境（只需一次）

```bash
pip install pillow numpy scipy
```

另外需要 **ffmpeg**（抽帧和编码都靠它）。Windows 从 ffmpeg.org 下压缩包，
把解压后 `bin/` 目录加进系统 PATH，`ffmpeg -version` 能打印版本就算好了。

#### 第一步：准备源素材

自己拍、录屏、AI 生成都可以，但有几条硬要求：

| 要求 | 为什么 |
| --- | --- |
| **背景是纯白**（或接近白的纯色） | 脚本按"够不够亮"判定背景，花哨背景抠不干净 |
| **角色和背景颜色差明显** | 浅灰、米白的角色会和背景糊在一起 |
| **固定机位，角色别出画** | 每帧独立处理，角色动没问题，但出画再回来容易断连 |
| **720×720 正方形** | 舞台按 `object-fit: contain` 适配，非正方形会留白 |
| **24fps、5 秒左右** | 和现有素材一致。临时态会被 `tempMs` 截断，拍长了也用不上 |

> **角色身上有白色怎么办？** 比如白衬衫、眼睛高光——不用担心。脚本用的是**连通域**填充，
> 只抠「和画面四边连通」的白色；被角色包在里面的白块不与边界连通，会原样保留。
> 这正是**不能简单粗暴地"把所有白像素变透明"**的原因。

#### 第二步：抽帧

**先建输出目录**——ffmpeg 不会自己创建，目录不存在会直接报
`Could not open file : frames/0001.png` 然后失败：

```bash
mkdir frames          # 必须先建，ffmpeg 不会替你建
ffmpeg -i 源视频.mp4 -vf scale=720:720 frames/%04d.png
```

得到 `frames/0001.png`、`0002.png`…。帧数 = 时长 × 帧率，5 秒 24fps 就是 120 张。
源视频不是白底（比如绿幕）的话，这一步之前先自己抠掉，本文只处理白底。

> 下一步的 `out/` 目录**不用手动建**，抠图脚本里有 `mkdir(parents=True, exist_ok=True)`，会自己创建。

#### 第三步：抠背景

把下面这段存成 `remove_bg.py`，和 `frames/` 放同级目录：

```python
#!/usr/bin/env python3
"""白底视频抠背景：只移除与画面四边连通的背景，角色内部的白色保留。

    python remove_bg.py frames/ out/ [容差]
"""
import sys
from pathlib import Path

import numpy as np
from PIL import Image, ImageFilter
from scipy import ndimage

SRC = Path(sys.argv[1] if len(sys.argv) > 1 else 'frames')
DST = Path(sys.argv[2] if len(sys.argv) > 2 else 'out')
TOL = int(sys.argv[3]) if len(sys.argv) > 3 else 32      # 0-255，越大抠掉越多

if not SRC.is_dir():
    sys.exit(f'找不到目录 {SRC}/，先跑上一步把视频抽成 PNG 帧')
if not sorted(SRC.glob('*.png')):
    sys.exit(f'{SRC}/ 里没有 PNG，确认抽帧那步跑成功了')

DST.mkdir(parents=True, exist_ok=True)

for p in sorted(SRC.glob('*.png')):
    rgb = np.asarray(Image.open(p).convert('RGB')).astype(np.int16)

    # 1. 候选背景像素：亮度够高。用亮度而不是"必须纯白"，容忍噪点和浅阴影
    cand = rgb.mean(axis=2) >= (255 - TOL)

    # 2. 连通域标记，只保留与四边相连的那一块 —— 内部白块不被误抠的关键就是这一步
    lab, _ = ndimage.label(cand)
    border = set(lab[0, :]) | set(lab[-1, :]) | set(lab[:, 0]) | set(lab[:, -1])
    border.discard(0)                       # 0 是"非候选"标签，不能当背景
    bg = np.isin(lab, list(border))

    # 3. 硬边 alpha：背景全透明，角色全不透明
    alpha = np.where(bg, 0, 255).astype(np.uint8)

    # 4. 向内收 1px 再羽化，消掉边缘残留的白色描边（不想要软边就删掉这两行）
    solid = ndimage.binary_erosion(~bg, iterations=1)
    soft = Image.fromarray((solid * 255).astype(np.uint8), 'L') \
                .filter(ImageFilter.GaussianBlur(0.8))
    alpha = np.minimum(alpha, np.asarray(soft))   # min 保证背景侧仍是 0，不外溢成光晕

    out = Image.merge('RGBA', (*Image.fromarray(
        np.clip(rgb, 0, 255).astype(np.uint8), 'RGB').split(),
        Image.fromarray(alpha, 'L')))
    out.save(DST / p.name)
    print(f'  {p.name}  判定为背景 {bg.mean() * 100:.1f}%')
```

跑：

```bash
python remove_bg.py frames out 32
```

第三个参数是容差：**抠不干净就调大，角色被啃掉就调小**。结果写到 `out/`。

每帧会打印判定为背景的像素占比——**这个数应该每帧都差不多**。
某一帧突然跳变，说明那帧有问题（角色出画、光线突变、或者背景上有阴影），回头单独看那张。

#### 第四步：编码成 VP9-alpha WebM

```bash
ffmpeg -framerate 24 -i out/%04d.png -c:v libvpx-vp9 -pix_fmt yuva420p \
       -crf 34 -b:v 0 -auto-alt-ref 0 -row-mt 1 -an idle.webm
```

- **`-auto-alt-ref 0` 是最容易踩的一个**：少了它，VP9 的 alpha 通道不生效，
  透明背景会变成**纯黑**。这条务必别省
- `-pix_fmt yuva420p` —— 带 alpha 的像素格式，末尾那个 `a` 就是 alpha
- `-crf 34 -b:v 0` —— 恒定质量模式，体积和画质平衡点。嫌糊调小 crf，嫌大调大
- `-an` —— 丢掉音轨，本来就没人听
- `-row-mt 1` —— 多线程，纯加速

七个状态各编一次，换掉最后的输出文件名。

#### 第五步：验证 alpha 真的进去了

**别只靠肉眼看播放器**——很多播放器拿黑色当底显示，透明和纯黑根本分不出来。用 ffprobe 查：

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt -of csv=p=0 idle.webm
```

输出必须是 **`yuva420p`**。如果打印的是 `yuv420p`（末尾少个 `a`），
说明 alpha 没进去，回去检查 `-auto-alt-ref 0` 和 `-pix_fmt` 那两句。

确认无误后，把 7 个文件丢进 `desktop-pet/videos/` 覆盖同名文件，`Ctrl+F5` 刷新即可。

#### 基础态和临时态分别注意什么

| 类型 | 注意 |
| --- | --- |
| **基础态**（idle / studying / working） | 会**无限循环播放**，首尾帧必须能自然衔接。做法：录一段首尾姿态一致的循环动作，或者把结尾几帧裁掉让动作回到起点 |
| **临时态**（alert / done / refuse） | 只播一轮。时长受 `App.Config.tempMs` 约束（alert 5s / done 3.5s / refuse 2.5s），**拍长了会被硬截断**，不如按要求裁剪好 |

> 素材的正确性要求、文件名清单、以及页面里不生效时该看哪条控制台日志，
> 都写在 **[desktop-pet/videos/README.md](../desktop-pet/videos/README.md)**（那份和素材放一起，
> 换素材时随手就能翻到）。本节的流程 + 那份的清单，两边不重复。

### 改 SVG 小猫的造型和动作

视频素材全都加载不上时会用这套内置动画，也可以主动加 `?novideo=1` 强制启用。

**造型**在 `desktop-pet/character/animation.js` 的 `svgMarkup()` 函数里（约 20-119 行），是一整段内联的 SVG 字符串，画布 `viewBox="0 0 200 200"`。里面分好了组，改颜色/改形状直接编辑对应分组：

| 分组 | 部位 |
| --- | --- |
| `g-tail` | 尾巴 |
| `g-body` | 身体 |
| `g-head` | 头 |
| `g-arm` | 手臂。实际有两个：`g-arm arm-l`（左）和 `g-arm arm-r`（右），CSS 里按 `arm-l` / `arm-r` 单独控制所以能做出左右手不同动作 |
| `prop-book` | 学习状态显示的书 |
| `prop-keyboard` | 工作状态显示的键盘 |
| `sign-exclam` | 提醒状态的感叹号 |
| `sign-cross` | 拒绝状态的 ✕ 符号 |
| `sparkle` | 完成状态的星光 |

**动作**（每个状态怎么动）在 `desktop-pet/style.css` 约 505-690 行，选择器形如：

```css
.stage[data-state="studying"] .arm-r {
  transform-origin: 30% 30%;
  animation: page-flip 2.2s ease-in-out infinite;
}
```

`.stage[data-state=...]` 前缀决定"什么时候动"，后面的类名决定"谁动"
（`.pet-all` 整体、`.g-head` 头、`.arm-l` / `.arm-r` 左右手、`.prop-book` 书本……）。
想改动作就改 `animation` 引用的那个 `@keyframes`（这里是 `page-flip`）。

改完记得 `Ctrl+F5` 刷新。

### 改状态文案、时长和归类

都在 `desktop-pet/app.js` 的 `App.Config`（约 132-178 行）。跟形象相关的几项是：

- **`stateLabel`** —— 徽章文字。想改叫法（或者换成英文）改这里
- **`stateByCategory`** —— 任务类别 → 基础态。想让「通用」类任务也显示学习状态，把 `general` 改成 `'studying'`
- **`tempMs`** —— 各临时态持续多久，素材比它长就会被截断
- **`refusePhrases`** —— 两级拒绝话术，含 `{category}` / `{title}` 占位

其余可调项（默认时长、提醒提前量、周期窗口等）见[第十二节](#怎么改一个任务默认多长时间之类的设置)的完整表格。

> 任务类别（`studying` / `working` / `general`）由标题关键词自动判断，关键词表在同文件 `App.Config.keywords`。
> `keywords.entertainment` 单独一组，决定什么话会被当成摸鱼（触发 `refuse`），
> 配合 `App.Config.entertainmentPatterns` 的宽松正则一起判定，详见[第七节](#七跨状态拒绝)。

### 换形象时的常见问题

**换了新素材但没生效？** 99% 是缓存。按 `Ctrl+F5` 强制刷新。还不行就检查文件名大小写。

**临时态播到一半就切走了？** 临时态的播放时长受 `App.Config.tempMs` 上限约束。素材比上限长的话会被截断——要么把视频剪短，要么调大 `tempMs` 里对应的值。

**非正方形的素材会怎样？** 不会被裁剪，按比例缩放到装得下为止，四周留白。想填满舞台就用正方形素材。

**看到的是橙色小猫？** 那是降级动画，原因和排查见[第十二节](#为什么我看到的是一只橙色小猫)。

## 十八、本地大模型（Ollama）

前面所有功能都**不联网**——说话靠 `dialog/input.js` 里的中文正则匹配。正则能接住「明天下午两点半上英语课」这种规整说法，接不住「这周找个时间把论文初稿弄完」这种没写明时间的句子，也不会闲聊。

**接一个本地模型就能补上这两块**：你随便怎么说它都能听懂，还能陪你聊天、结合你的日程回答问题。模型跑在你自己电脑上，**对话内容不出局域网**。

> **默认是关的。** 关着的时候不产生任何网络请求，行为和装这个功能之前一模一样。上面所有文档在开关关闭时都成立。

### 三步开起来

**1. 装 Ollama 并拉一个模型**

到 <https://ollama.com/download> 下载安装（Windows / macOS 都有）。装完打开终端：

```bash
ollama pull qwen3:4b
```

`qwen3:4b` 约 2.5GB，纯 CPU 也能跑，是默认值。机器有独显、内存 16GB 以上可以换 `qwen3:8b`（约 5GB，答得更稳但更慢）；内存小的老机器用 `qwen3:1.7b`（约 1.4GB，快但容易答歪）。**换模型前必须先 `ollama pull` 把新模型拉到本地，页面只负责填名字连过去，不会替你下载。**

**2. 允许浏览器跨源访问**

用 `file://` 双击打开页面时，浏览器会因为同源策略拦掉对 `127.0.0.1:11434` 的请求。设置一个环境变量再重启 Ollama：

```powershell
# Windows PowerShell（设完要退出托盘里的 Ollama 再重新打开）
setx OLLAMA_ORIGINS "*"
```

```bash
# macOS / Linux
export OLLAMA_ORIGINS="*"
```

`*` 只表示"谁都能连我这个本地端口"，而 Ollama 默认只监听本机，**不会因此把模型暴露到公网**。

> **设完必须真的重启 Ollama（退出托盘图标再打开）**。环境变量只在进程启动那一刻读一次，
> 正在跑的那个进程不会自己更新——不重启，页面会一直停在「未连接」，看起来像设置没生效。
>
> **不想设环境变量也行**：`cd desktop-pet` 后跑 `python -m http.server 8080`，
> 浏览器开 `http://localhost:8080/`，Ollama 默认就放行 localhost 来源。
> 但 `file://` 和 `http://localhost:8080` 是**两个独立的存储空间**，原来双击时存的日程
> 在新地址下看不到。要带过去：双击打开 → 顶部「导出备份」下载一个 JSON → 换 8080 地址打开 → 「导入备份」。

**3. 在页面里打开开关**

顶部工具栏点 **「本地模型：关」**，按钮变绿、文字变成「本地模型：开」：

| 步骤 | 你会看到 |
| --- | --- |
| 点「本地模型：关」 | 按钮变绿写「本地模型：开」，底部提示「本地模型已开启，正在检测连接…」，宠物说「本地模型开啦～」 |
| 探活（`GET /api/tags`，2.5 秒超时） | 徽章显示「检测中…」 |
| 结果 | 通 →「已连接（N 个模型）」；不通 →「未连接」 |

**模型名要自己填。** 点 **⚙** 展开设置面板：

| 字段 | 怎么填 |
| --- | --- |
| 接口地址 | 默认 `http://127.0.0.1:11434`，模型装在本机就不用改。装在局域网另一台机器上填 `http://192.168.x.x:11434` |
| 模型名 | 手输，默认 `qwen3:4b`。**先 `ollama list` 看一眼有哪些**，名字要一模一样（含 `:4b` 这样的标签） |
| 「保存」 | 写进浏览器存储，并立刻重新探活 |
| 「重新检测」 | 不改配置，只重新打一次探活 |

模型名输入框带自动补全：探活成功后，Ollama 返回的模型清单会灌进候选里，点一下就能选，不用手打全名。

> **模型名打错不会报错。** 服务器本身是通的，所以徽章会变成「**已连接，但没有 xxx**」——看到这句就是名字写错了，去 `ollama list` 核对一下。

连不上时徽章显示「未连接」，并且**不影响任何原有功能**——加日程、提醒、导入导出走的还是原来那套正则。

### 打开之后有什么不一样

| 场景 | 关着 | 开着 |
| --- | --- | --- |
| 「明天下午三点到四点项目评审会议」 | 正则接住，直接建日程 | 正则先接，同样的结果 |
| 「**这周找时间**把论文初稿弄完」 | 听不懂，回「没太听懂」 | 模型补全意图，**复述给你确认**，回复「确认」才建日程 |
| 「我今天还有什么安排」 | 正则接住，列出清单 | 同上（模型不参与） |
| 「你好呀，今天心情怎么样」 | 听不懂 | 聊天回复，边生成边显示 |
| 「我明天有什么要做的？」 | 听不懂 | 结合你的日程表回答 |

**三个关键设计**：

- **正则优先，模型兜底**。只有正则没接住的句子才会送给模型。所以常用说法永远是**毫秒级**响应，模型再慢也不拖累它们。
- **模型不直接写数据**。它只输出一个意图对象，后面照样走 `App.Controller` 里那些 `do*` 处理器——冲突检测、重叠询问、娱乐拦截全都还在。**不会出现"模型把日程写乱了"这种事**。
- **模型解析出的写操作，先复述再执行**。4B 模型会理解错，而删错、改错一条日程的代价比多问一句大得多，所以添加 / 修改 / 删除 / 复制都会先跟你对一遍，回复「确认」才落库。查询（「今天有什么安排」）和闲聊是只读或纯文字，不拦，直接答。

```
你：这周找时间把论文初稿弄完
宠物：我理解你要添加 周五 14:00–15:00「论文初稿」，对吗？（回复「确认」或「取消」）
你：确认
宠物：好的，已添加 周五 14:00–15:00 论文初稿（学习）。
```

> 具体日期时间是**模型补的**，觉得不对不用重新组织语言，直接说对的说法（比如「改成周六上午」）——待确认就撤掉，这句按新指令处理。
> 关掉模型时同一句话仍是「没太听懂」：确认门只装在模型通路上，正则通路只在自己有把握时才接住，解析出来直接执行。

### 它有多慢？

本地小模型的速度取决于你的硬件。**纯 CPU 推理时实测**（qwen3:4b，643 token 的意图提示词）：

| 阶段 | 耗时 |
| --- | --- |
| 读提示词（prompt eval） | 约 9.5 秒 |
| 生成 48 token 的意图 JSON | 约 3.2 秒 |
| **一次加日程总计** | **约 13 秒** |

有独显（GPU 加速）会快一个量级，通常在 1~3 秒内。聊天更慢一点，但**是流式输出的**——第一个字大约 3 秒出现，然后边生成边往外蹦，不用干等。

等待期间宠物会切成「交流中」状态循环播放 `talking.webm`，对话框上面显示「让我想想…」，所以不会看起来像卡死了。

**如果超过 30 秒还没出结果**，会判超时：状态降级为「未连接」，这句话退回离线通路处理（你会看到「没太听懂」），而不是石沉大海。

### 出问题了

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 徽章一直「未连接」 | Ollama 没启动 / 地址不对 | 看托盘里有没有 Ollama；命令行跑 `ollama list` 确认能通 |
| 提示要设 `OLLAMA_ORIGINS` | 浏览器拦了跨源请求 | 见上面第 2 步，**设完必须重启 Ollama** |
| 之前能用，突然「未连接」 | Ollama 重启后没加载模型，或端口被占 | 点 ⚙ 里的「重新检测」 |
| 回复里带一堆"首先…让我想想…" | 不是本项目的 bug，是模型在"思考" | 项目已经用 JSON 结构约束压制住了；换成更大的模型（`qwen3:8b`）更稳 |
| 每次回答都很慢 | 纯 CPU 推理 + 模型太大 | 换 `qwen3:1.7b`，或让 Ollama 用上独显 |

**连不上会不会影响正常用？** 不会。探活失败只是把按钮显示成「未连接」，你照样能加日程、看提醒、导入导出——走的还是原来那套正则。

### 隐私

- 请求只发给**你自己填的地址**，且必须是本机或局域网地址（`localhost` / `127.*` / `10.*` / `192.168.*` / `172.16-31.*`）。填公网地址会被拒绝并回落到默认值——这是防止设置被篡改后把你说的话发到外网。
- 发给模型的内容有三块：你的那句话、你的日程清单（今天+明天，最多 30 条）、最近 12 轮对话。
- **对话记录只存在内存里**，刷新页面就没了，不写 LocalStorage，也不落盘。
- 开关关着的时候，以上全部不发生。

### 想调参 / 想验证

可调项在 `App.Config.llm`（`desktop-pet/app.js`）：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `healthTimeoutMs` | `2500` | 探活超时 |
| `intentTimeoutMs` | `30000` | 意图提取超时。纯 CPU 上实测要 13 秒，别调太小 |
| `chatTimeoutMs` | `90000` | 聊天回复总超时（也是「交流中」动画的兜底上限） |
| `intentMaxTokens` | `256` | 意图 JSON 的输出上限 |
| `chatMaxTokens` | `512` | 聊天回复的长度上限 |
| `historyTurns` | `12` | 记着最近多少轮对话 |
| `contextTaskDays` | `2` | 提示词里带几天的日程（今天+明天） |
| `contextMaxTasks` | `30` | 提示词里最多列几条任务 |

想验证接得通不通，在仓库根目录跑：

```bash
npm test                      # 离线：全部 9 个套件 463 条断言，不联网。test-llm.js 占其中 169 条
npm run test:live             # 联网：真连 Ollama 跑一遍完整链路（32 条）
```

`test-llm-live.js` 需要 Ollama 在跑。连不上、或者模型没 pull，它会**打印跳过原因并以退出码 0 结束**，不会让回归挂掉。想指定地址或模型：

```bash

```

**改了提示词或换了模型之后，跑一次 live 测试**——离线测试里模型是打桩的，管不到"真模型听不听话"。
