# 桌面虚拟宠物日程助手 V2.0 — 使用说明

一个跑在浏览器里的桌面宠物：**它按你的日程表自动切换状态，任务开始时提醒你、任务进行中陪着你、任务结束为你庆祝，任务期间你想摸鱼还会被它拦下来。**

纯前端实现，无需安装、无需服务器、无需联网。

## 一、快速开始

**双击 `desktop-pet/index.html` 即可。**

建议用 Chrome 或 Edge。第一次打开是空闲状态，角色站在画面中央，右下角对话框会跟你打招呼：
没排日程时说「你好呀～我是你的桌面日程小助手……」，已经有日程时会改成「欢迎回来～今天还有 N 项安排」。

想直接看完整效果，打开 `index.html?demo=1`，会自动灌入几条演示日程（含一条"正在进行中"的任务），宠物立刻进入工作/学习状态。

> **如果看到的是橙色小猫而不是紫发角色**，说明视频素材没加载上、自动降级到了内置 SVG 动画。功能完全不受影响，七种状态一样能切换。原因和解决办法见 [第十二节](#为什么我看到的是一只橙色小猫)。

> **想让 `data/backgrounds/`、`data/wallpapers/` 里新放的图自动出现在面板里？**
> 双击打开时，在面板底部点一次 **「授权 data 目录…」** 选择 `desktop-pet/data`；
> 或者运行 `npm run serve` 用本地服务器打开。详见[第十节](#十界面外观舞台背景与界面壁纸)。

> **想在手机或平板上用？** 见 [第十六节](#十六移动端使用)。

## 三、添加日程

### 方式一：直接跟它说（最快）

在底部输入框打一句中文，回车发送：

```
明天下午两点半上英语课
晚上七点有个会议
后天9点到11点数学复习
明天下午2点到4点开会
```

它会回一句确认（"已添加「英语课」……"），右侧计划表立刻出现这一条。

### 方式二：批量导入安排表（课表 PDF / 模板 PDF / CSV）

除了自己填模板，**教务系统导出的课表 PDF 可以直接导入**：选完文件它自己认出版面，
把「星期一 3-4 节，第 1-9 周」这类信息展开成一条条具体日程，不用手抄。

1. 点顶栏 **「下载模板」**，得到 `schedule_template.pdf`；或者直接用你教务系统导出的课表 PDF
2. 用 WPS / Adobe / 浏览器 打开模板 PDF，直接在表格里填（PDF 里的说明文字导入时自动忽略）
3. 点 **「导入安排表」** 选中文件（课表 PDF、模板 PDF、`.csv` 都行，格式见第四章）
4. 弹窗告知解析到多少条、有多少错误，然后回复：

   | 回复 | 效果 |
   | --- | --- |
   | `确认`（或 `是` / `对` / `好` / `导入`） | **合并**导入，和现有日程并到一起 |
   | `替换` | **清空现有日程**后再导入，只保留文件里的 |
   | `取消` | 放弃本次导入 |

重复的条目会自动跳过，不会产生两份。

#### 直接导入教务系统的课表 PDF

选完文件直接出结果，不用回答任何问题。弹窗里会说明：

```
识别为课表：23 门课。学期第 1 周按 2026-08-31（周一，按课表的学年学期推断）计算；
如果不对，直接回复正确的第 1 周周一日期（YYYY-MM-DD），我会重新算。
```

- **学期第 1 周周一是推断的**（课表 PDF 里通常没有这个信息）：优先用你上次回复过的日期；
  老版课表按「打印时间」往回推，新版表格按「2026-2027 学年第 1 学期」的表头估算
  （第 1 学期取 9 月 1 日、第 2 学期取次年 3 月 1 日所在周的周一）。
  **推断值不对就回复一个日期**，它当场重算并记住，之后导入同校其它课表不用再说。
  日期只会整体平移，课程和时间不受影响。
- **课程名后面自动带上教室**（如 `软件测试与管理 H4-413`），地点从课表里读，方便直接看。
- 已经上过的课自动跳过；单双周、跨页的课表都能认。
- 只认「星期 × 节次」这种网格课表。如果你教务系统的版面不一样，会明确提示解析失败，不会静默丢课。

> 「替换」会删掉你现在所有的日程，用之前想清楚。误操作的话只能用「导出备份」的文件救回来。

### 方式三：周期日程

安排表的 `date` 列可以直接写规则词，导入时自动展开成具体日期，窗口是**今天起往后数 14 天**（今天是第 0 天，所以一共覆盖 15 个日期）：

```
工作日,09:30,11:30,写代码,working      ← 展开成这个窗口里所有工作日
每天,22:30,23:00,睡前复盘              ← 每天一条（category 留空会自动归类）
周三,14:00,15:30,英语精读              ← 每周三一条
```

> 窗口长度是 `App.Config.materializeDays`（默认 14）。窗口外的规则不会提前生成，
> 但**只要导入时用了规则词，之后每天打开页面都会自动往后补**，不需要重新导入。

## 四、导入格式参考

**PDF 模板**：模板就是一张五列表格（`date,start,end,title,category`），填好后直接导入。应用内部会把
PDF 表格按列位置还原成 CSV，再走同一套解析与校验，所以下面列的规则、规则词、`#` 注释对两者完全一致。

要用 PDF 导入，注意三点：

- 必须是**文字型 PDF**（文字可以选中复制）。扫描件、图片型 PDF 没有文字层，提不出内容，会提示导入失败
- 用模板改，**不要改动列的位置**；每个单元格保持单行，不要手动换行
- 表格之外的文字（模板顶部的说明、页脚）会被自动忽略，不会变成日程；但**别在表格外随手写数据**
- 不限于本模板：自己做的五列表格（表头文字一致）另存/打印成 PDF 也能导入，不挑生成工具

改不了 PDF 也没关系：**CSV 一样能导入**，格式如下。

### 课表 PDF（教务系统导出）

不是五列表格也没关系 —— 教务系统那套「星期 × 节次」的网格课表能直接认出来，见第三章方式二。
这类 PDF 常见两个坑，应用都已经处理：

- **文字提不出来**：很多课表用未内嵌的中文字体，字形到文字的对照表放在 PDF 外面。
  应用内置了 GB 系 CMap（`lib/pdfjs/cmaps.js`，简体中文），双击打开也能解析
- **版面有两种**：老版教务系统导出的网格会转 90°（节次沿横向、星期沿纵向、格子里的文字竖排）；
  新版 WPS / Excel 导出的是常规表格（星期为列、节次为行、格子内按列宽折行）。
  识别逻辑按坐标还原两种版面，不靠「看起来像表格」
- **节次列可能只有时间**：有的导出会把「节次」列压成 `09:00-09:40` 这样的纯时间段。
  这时按页码和从上到下的顺序把它们当成第 1、2、3… 节，课程里的 `(3-4节)` 照样能对上

用到的信息：`(3-4节)1-9周(单)` → 节次对应的时间、周数范围、单双周。
`场地:H4-413（江）` → 房间号（校区后缀去掉）拼到课程名后面。其余元数据（教师、教学班、
学分等）会读完但不进日程，避免标题太长。

### CSV 格式

表头固定为 `date,start,end,title,category`（顺序不能变）：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| `date` | ✅ | `YYYY-MM-DD` 具体日期；或规则词 `每天` / `工作日` / `周末` / `周一`~`周日` |
| `start` | ✅ | 24 小时制 `HH:MM` |
| `end` | ❌ | 留空默认 60 分钟；跨天写 `00:30(+1)` |
| `title` | ✅ | 任务名称。CSV 里含逗号**要用双引号包起来**；PDF 里按列边界切分，怎么写都行 |
| `category` | ❌ | `studying` / `working` / `general`，也可写中文 `学习` / `工作` / `通用`；留空则按标题关键词自动判断 |

**一个完整的例子：**

```csv
date,start,end,title,category
# 以 # 开头的行是注释，不会被导入
2026-09-21,09:00,10:30,英语听力训练,studying
2026-09-25,19:00,20:00,项目周会,working
2026-09-26,23:00,00:30(+1),夜间实验收尾,working
工作日,08:30,09:00,晨读背诵,studying
每天,12:10,12:50,午休,general
周一,14:00,15:30,高等数学复习,
周末,10:00,11:30,兴趣手绘,
```

支持的细节：UTF-8 BOM、双引号转义、字段内换行、`#` 注释行、空行跳过。表头写错会整份拒绝并说明原因；单行时间格式错误只跳过该行，其余正常导入。PDF 导入复用同一套校验与规则词展开，报错里的行号对应重建出来的表格行。

**会被跳过的行**（导入时会逐条列出来）：

- `title` 超过 40 个字
- `date` 是**已经过去的日期**——过去的日程排了也没意义，直接忽略
- 和前面某行完全重复的条目

另外 `每天` 还有一个等价写法 `每日`，两个都认。

### 新增

| 你可以说 | 效果 |
| --- | --- |

| --- | --- |

| `把三点的会议删掉` | 按时间+标题匹配删除 |

匹配到多条时会列出候选，回复序号即可：`找到多条安排，回复序号告诉我删除哪一个：`

### 修改

| 你可以说 | 效果 |
| --- | --- |

### 查询

| 你可以说 | 效果 |
| --- | --- |
| `今天还有什么安排` | 列出今天剩余日程，并在右侧计划表高亮 |
| `明天有什么` | 列出明天的日程 |
| `后天12:00后还有什么安排` | 只看某个时刻之后的安排（跨过 12:00 的任务也算） |
| `今天12点前的安排` | 只看某个时刻之前的安排 |

| `今天上午有什么安排` | 按上午时段筛选；明确问了时段时，已经结束的安排也会列出来 |
| `明天14:00到16:00的安排` | 按明确的时间区间筛选 |
| `接下来还有什么安排` | 从此刻起列出剩余安排 |
| `英语课什么时候` | 在所有未来日程里找这个事项，列出每一次 |
| `英语课还有多久` | 直接回答距离下一次还有多长时间；正在进行就说正在进行 |
| `下一项安排是什么` | 直接说出最近的一条安排 |

### 复制整天（把某天的安排整批搬到另一天）

| 你可以说 | 效果 |
| --- | --- |
| `把明天的安排复制到周五` | 明天**全部未完成**的安排各复制一份到周五，**源日原样保留** |
| `把9月20日的安排复制到9月25日` | 同上，用具体日期 |
| `把周二的安排拷贝到周三` | `拷贝` 同义 |
| `把明天的安排抄到后天` | `抄到` 同义（但 `抄作业` 不会被误判） |
| `把安排复制到周五` | 左边不写日期 = **今天** |

只做**整天**搬运。左边写了名字或时间（如 `把明天下午三点的会议复制到周五`）会被拦住并提示改写；想搬单条请用上面的 `挪到` / `改到`。

源日**已经完成**的安排不复制，跳过了几条会一并告诉你。

#### 时间撞上了怎么办

目标日已有安排和要复制过去的时间重合时，会把**撞上的两条放在同一个框里**逐对列出来，一次问完：

> 把明天的 3 项安排复制到周五（另有 1 项已完成，不复制），其中 1 对时间撞上了：
> - 要复制 **英语课** 09:00–10:00 ／ 已有 **晨读** 09:30–10:30
>
> 回复「重叠」撞上的两条都留下，回复「更换」把撞上的合并成一条（名字用逗号连起来，如「英语课,晨读」），回复「取消」放弃。

| 回复 | 效果 |
| --- | --- |
| `重叠`（`都留` / `保留` 也行） | 撞上的两条**都留下**，各占各的时间 |
| `更换`（`替换` / `合并` 也行） | 撞上的两条**合并成一条** |
| `取消` | 什么都不动，两边都保持原样 |

**「更换」具体怎么合**：名字用逗号接起来，时间段取**并集** —— 先开始的那个的头时间，到最后一个结束的那个的尾时间。

| 要复制的 | 目标日已有 | 合并结果 |
| --- | --- | --- |
| `英语课` 09:00–10:00 | `晨读` 09:30–10:30 | `英语课,晨读` **09:00–10:30** |
| `实验课` 10:00–11:00 | `答疑` 09:45–10:30 + `自习` 10:30–11:15 | `实验课,答疑,自习` **09:45–11:15** |

没撞上的安排照原样复制过去。一条已有安排同时被多条撞上时，只并进**开始最早**的那条。

复制出来的副本是**独立的一次安排**，不再带原来的周期规则 —— 源日是个「每天」的安排，复制到某一天也只有那一天多一条，不会跟着天天长。

> 撞车只比**目标日当天**。跨天任务（如 23:00–01:00）落过去时，次日凌晨那半段不会去和次日的安排比对，这点和「新增」的重叠检查范围一致。

### 批量修改 / 批量删除（按星期 + 标题定位）

一句话里同时出现**范围词**（`都` / `所有` / `全部` / `每` / `各`）和**动作**（`改` / `挪` / `删` / `调整`）时，
就会按批量处理：先找出所有命中的安排，列出来问一句，回复 `确认` 才真正执行。

| 你可以说 | 效果 |
| --- | --- |
| `把周一的数据库系统原理都改到周二晚上相同的时间` | 所有周一的这门课移到周二，**开始时间、时长都不变** |
| `把所有周一的数据库系统原理都改到晚上八点` | 只改开始时间，结束时间按原时长顺延 |
| `把所有周一的数据库系统原理都往后挪半小时` | 整体平移 30 分钟（`提前一小时` 就是往前挪） |
| `把「数据库系统原理 H3-204」改名成「数据库原理」` | 全库同名安排一起改名 |
| `周二的走在“前列的广东实践 学生发展中心401”改名成“前列的广东实践”并改放到周三晚上` | 改名 + 换星期可以写在一条里，时间保持不变 |
| `把所有周一的数据库系统原理都删掉` | 批量删除，同样先确认 |

几条规则：

- **定位条件**：星期（`周一`…`周日`）+ 标题片段，两者可以只写一个。标题按空格归一后做包含匹配，
  `数据库系统原理` 能命中 `数据库系统原理 H3-204`。书名号 / 引号里的名字优先当作完整标题。
- **`相同的时间` / `同一时间段`**：只换星期，不动钟点。`晚上` 这类时段词单独出现时也只换天，
  不会把时间改成 20:00；要改钟点请写 `晚上八点` 这样的具体时间。
- **同周优先**：目标星期在本周还没到就落在本周，已经过了就落到下一周，不会把课移到过去。
- **已完成的不动**：批量修改和删除默认跳过 `done` 的任务，结果里会告诉你跳过了几条。
- **多条才确认，一条直接做**：只命中一条时按普通修改/删除执行，不弹确认。
- **冲突照常报告**：移动后和同一天已有安排重叠的，会在结果里列出条数和标题。
- 支持改时长：`都改成 90 分钟`、`都延长半小时`。

### 按星期聚合查询

| 你可以说 | 效果 |
| --- | --- |
| `每周一都有什么安排` | 列出**所有未来周一**的安排，按日期分组 |
| `周一的课都有哪些` | 同上；`课` 这类泛称不会被当成标题去过滤 |
| `所有周三的安排` | 同上 |

`下周一` / `这周一` 仍然按具体某一天查，不会变成聚合查询。

### 时间表达的完整支持

- **日期**：今天 / 今日 / 今儿 / 明天 / 明日 / 后天 / 大后天 / **今晚 / 明晚 / 后晚** / 周一~周日 / 这周五 / 下周三 / `2026-09-21` / `9月21号`
- **时段**：上午 / 早上 / 早晨 / 清晨 / 中午 / 下午 / 傍晚 / 晚上 / 夜里 / 凌晨 / **晚**（单字也算，`晚8点` = `晚上8点`）
- **时间**：`三点` `三点半` `三点一刻` `三点三刻` `三点二十` `15:30` `15点30分`；中文数字 `十点` `十一点` `十二点` 都认
- **区间**：`下午2点到4点` `下午2点至5点` `晚上7点~9点`。**终点没写时段时会继承起点的**，所以「下午2点到4点」是 14:00–16:00 而不是跨天到凌晨 4 点
- **特殊**：`下午十二点` → 12:00；`晚上十二点` → 次日 00:00；`晚上10点到2点` → 22:00 到**次日** 02:00（终点明显早于起点时按跨天理解）

### 听不懂的时候

它不会瞎猜。解析不了会如实说明并给例子：

| 回复 | 含义 |
| --- | --- |
| `没太听懂你想做什么～可以说「添加」「删除」「修改」「查询」「复制」相关的话。` | 没识别出意图 |
| `要安排在几点呢？` | 识别出要新增，但没说时间 |
| `这件事叫什么名字呢？` | 识别出要新增，但没说做什么 |
| `没听清是哪一天，可以说明「今天」「明天」或具体日期。` | 日期有歧义 |
| `要复制到哪一天呢？说「把明天的安排复制到周五」这样就行。` | 说了「复制」但没给目标日 |
| `复制整天是把那一天的全部安排都搬过去，名字和时间不用写哦～` | 复制语句里带了名字/时间（只支持整天） |

### 重叠与确认

新增的时间如果和已有安排重叠，会先问一句：

> 这个时间和「项目周会」重叠了，确定要添加吗？（回复「确认」或「取消」）

回复 `确认` / `确定` / `是` / `对` / `好` / `好的` / `嗯` / `y` / `yes` / `继续` / `添加` 都算同意；回复 `取消` / `算了` / `不要` / `不用` / `否` / `n` / `no` 放弃。

## 六、角色状态说明

### 两套形象，自动选

| 模式 | 长什么样 | 怎么触发 |
| --- | --- | --- |
| `video` | 内置形象 zhenzhu（默认），或导入的形象包 | 内置目录 / 包内有能播的视频素材 |
| `svg` | 橙色小猫 + CSS 动画 | 视频素材缺失、加载失败，或加了 `?novideo=1` |

启动时会先探测 `videos/idle.webm` 作为兜底素材（根目录没有就继续），随后恢复上次选择——默认是
内置形象 zhenzhu，直接读 `videos/zhenzhu/`；都不可用时自动降级到内置 SVG 小猫，不需要手动切换。
当前用的是哪套，按 `F12` 在控制台输入：

```js
document.getElementById('stage').dataset.mode      // 'video' 或 'svg'
document.getElementById('stage').dataset.state     // 当前状态，如 'studying'
```

### 七种状态

**全部由系统本地时间 + 你的日程表现场推导**，不需要你手动切换。分基础态和临时态两类：

**基础态**（循环播放，直到任务状态变化）：

| 状态 | 徽章 | 触发条件 | 角色表现 | 素材文件 |
| --- | --- | --- | --- | --- |
| `idle` | 空闲中 | 当前没有进行中的任务 | 托腮侧卧、轻微呼吸摆动 | `idle.webm` |
| `studying` | 学习中 | 正在进行「学习」类任务 | 坐在书桌前用笔写字 | `studying.webm` |
| `working` | 工作中 | 正在进行「工作」/「通用」类任务 | 端着茶杯喝茶 | `working.webm` |

**临时态**（播完一轮回到基础态）：

| 状态 | 徽章 | 触发条件 | 角色表现 | 素材文件 | 时长 |
| --- | --- | --- | --- | --- | --- |
| `alert` | 提醒 | 任务**刚开始**的 90 秒内 | 举手挥动 + 感叹号 + 气泡播报 | `alert.webm` | 5 秒 |
| `done` | 任务完成 | 任务**刚结束**时 | 闭眼笑、双手合拢 + 完成播报 | `done.webm` | 3.5 秒 |
| `refuse` | 温馨提醒 | 任务进行中你提出娱乐请求 | 皱眉握拳 + 抖动 + 红光 + 拒绝话术 | `refuse.webm` | 2.5 秒 |
| `talking` | 交流中 | 本地模型正在理解 / 组织回复 | 说话、讲解手势 | `talking.webm` | 循环到回复结束 |

> `talking` 只在**开启本地大模型**（[第十八节](#十八本地大模型ollama)）后才会出现，且是唯一**循环播放**的临时态：
> 回复要几秒就循环几秒，由回复返回时主动收掉，默认 90 秒只是兜底上限。开关关着时它永远不会出现。

**另外两个提醒态**：`warnStart`（开始前 5 分钟提醒）和 `warnEnd`（结束前 10 分钟打气）。
它们**不占独立素材**，直接复用 `alert` / `done` 的视频，只把徽章文字换成「提醒」和「加油」。

**一个重要的设计**：状态不是"事件推送"而是"**每一秒从当前时间和日程重新算一遍**"。所以合上笔记本两小时再打开、系统休眠、手动改系统时间、跨过午夜——它都能自己算对，不会因为漏掉某个事件就卡在错误状态。

**重新打开页面不会重播提醒**。比如任务 14:00 开始，你 14:30 才打开页面，它会直接进入"学习中"，而不是弹一次"到时间了"。

> 想换成自己的角色形象？见 [第十七节](#十七虚拟形象自定义)。

## 七、跨状态拒绝

这是这个项目最有意思的机制。**任务进行中**，你如果想摸鱼：

```
你：我想玩游戏
宠物：现在是学习时间哦，专心完成任务再玩吧～     ← 抖动 + 红光
```

- **不会打断日程**——拒绝动画播完自动回到任务状态
- **不会写入日程表**——娱乐请求根本不会入库
- **再说一次会更严厉**：

  ```
  你：那我看个视频
  宠物：不行哦！英语听力训练还没结束呢，娱乐的事等完成了再说！
  ```

- **空闲时间提娱乐**：不会拒绝，只会安抚一句"现在是空闲时间，想放松就玩一会儿吧～不过到了任务时间我会提醒你的。"
- **带具体时间的娱乐安排**（比如"周五晚上八点看电影"）算正常日程，照常入库，不会被拒绝。
  入库时**类别会归成「通用」**——娱乐不单独占一种角色动画，宠物到点显示的是工作状态

### 怎么判定"这是娱乐请求"

不用一字不差地说关键词——**整句话里只要出现娱乐词就算**，前后加多少字都行：

| 说法 | 命中 |
| --- | --- |
| 我想玩游戏 | ✅ 句子里含「玩游戏」 |
| 现在好想打游戏啊 | ✅ 含「打游戏」 |
| 我想玩一会儿游戏 | ✅ 动词和宾语被隔开，靠宽松匹配兜住 |
| 看个视频放松下 | ✅ |
| 帮我整理追剧片单 | ⚠️ 也会被判成娱乐（句子里有「追剧」），属于误伤，换个说法即可 |
| 明天下午三点整理游戏攻略 | ❌ 不算——「玩游戏」这个词被拆开了，且带了具体时间，按普通日程入库 |

**判定分两步**：

1. **精确子串**：句子里含 `玩游戏 / 打游戏 / 看视频 / 刷短视频 / 刷手机 / 追剧 / 刷剧 / 看电影 / 看动漫 / 睡觉 / 躺会 / 摸鱼 / 打盹` 任意一个
2. **宽松匹配**：动词和宾语之间最多隔 4 个字也算，覆盖「玩一会儿游戏」「看个视频」「刷会儿手机」这类口语说法

改这两组词在 [app.js](../desktop-pet/app.js) 的 `App.Config.keywords.entertainment` 和 `App.Config.entertainmentPatterns`。想加"打牌""逛街"之类，往第一个数组里加就行。

> 注意：拒绝只在**任务进行中**才触发（见本节开头）。空闲时同一个句子只会得到安抚，不是没识别出来。

## 八、提醒机制

除了任务开始/结束的准点播报，还有两个**提前提醒**（默认开启，无需设置）：

| 时机 | 说什么 | 角色表现 |
| --- | --- | --- |
| 任务**开始前 5 分钟** | 「×××」还有 5 分钟就要开始了，准备一下哦～ | 举手挥动（复用提醒动画） |
| 任务**结束前 10 分钟** | 「×××」还有 10 分钟就结束啦，坚持住，胜利在望～ | 闭眼笑（复用完成动画） |

细节：

- **结束前打气只针对当前正在进行的那个任务**，不会被重叠的其他安排反复打扰
- **每条只播一次**，不会每分钟重复
- **迟到补报**：如果打开页面时已经进入提醒窗口（比如任务 14:00 开始，你 13:57 才开页面），会立刻补播一次
- **跨午夜的任务也能正确处理**，不会因为日期翻转而漏播或重播
- 提前量可以调：改 `app.js` 里 `App.Config` 的 `warnStartMin` / `warnEndMin`（见第十二节）

## 九、每日总结

当天所有安排**全部完成**时，宠物会播报一次：

> 今天的 3 项安排都完成啦，辛苦了！

**只播一次**。当天再打开页面也不会重复播；第二天自动重置。

## 十、界面外观：舞台背景与界面壁纸

这是两个不同的东西，作用范围不一样，可以同时用：

| | 舞台背景 | 界面壁纸 |
| --- | --- | --- |
| 按钮 | 更换背景 | 界面壁纸 |
| 作用范围 | 只铺在宠物舞台那块 | 铺满整个窗口，像电脑桌面壁纸 |
| 预设 | 1 张（紫色，放 `data/backgrounds/`） | 1 张（中山装·人生哲理，放 `data/wallpapers/`） |
| 自动发现文件夹里的图 | ✅ `data/backgrounds/` | ✅ `data/wallpapers/` |
| 能导入本地图片 | ✅ 会写回对应文件夹 | ✅ 会写回对应文件夹 |

> 两者的图片**分开放**：舞台背景在 `data/backgrounds/`，界面壁纸在 `data/wallpapers/`。
> 换壁纸的面板里只会列出 `data/wallpapers/` 下的图，不会混进背景图。

### 图片自动同步与落盘

**手动放图**：把图片直接拖进 `data/backgrounds/` 或 `data/wallpapers/`，重新打开对应面板就能看到，
不需要改代码或重启应用。支持 `.jpg / .jpeg / .png / .webp / .gif`，SVG 会被忽略。

**双击打开（file://）**：第一次需要点面板底部的 **「授权 data 目录…」**，选择 `desktop-pet/data`
文件夹（选 `desktop-pet/` 也会自动找到 `data/`）。授权后：

- 面板会列出文件夹里的所有图片；展开面板时会自动重扫
- 「本地图片…」导入的图会**真正写进对应文件夹**，文件名是「原文件名-日期-时间.jpg」，
  例如 `二次元-20261019-134500.jpg`
- 设置里存的是短路径，不再把整张图塞进 LocalStorage；旧版本存成 base64 的图会在授权后自动迁移
- 浏览器重启后如果提示「授权已过期」，点 **「重新授权」** 即可；在授权弹窗里选
  **「每次访问都允许」** 可以减少重复提示

**本地服务器模式**：在仓库根目录运行 `npm run serve`（Windows 也可以双击 `start-server.bat`），
打开 `http://127.0.0.1:8123/`。这种模式下不需要目录授权，图片列目录和写入全自动。

> 如果当前打开方式两者都不支持（例如某些 IDE 预览窗口），导入的图会退回旧行为，
> **只保存在浏览器里**；面板底部会明确提示，并给出解决办法。

> HTTP 模式与双击打开是**两个独立的存储空间**：日程、设置、形象包互不相通。
> 想继续用原来的数据，就保持双击打开 + 目录授权。

### 舞台背景

点 **「更换背景」**，展开一排缩略图，点一张就换上了；点「无」恢复纯色。也可以点顶栏的 **「清除背景」**。

点 **「本地图片…」** 可以选自己电脑上的图当舞台背景，处理方式与界面壁纸相同（等比压到最长边不超过 1920 像素，转成 JPEG），原图不动。

### 界面壁纸

点 **「界面壁纸」**：

- 点预设缩略图直接换
- 点 **「本地图片…」** 选自己电脑上的图，会自动处理（等比压到最长边不超过 1920 像素，转成体积更小的 JPEG），原图不动
- 点「无」恢复纯色，或点 **「清除壁纸」**

**换上壁纸后，界面上的面板会变成半透明**，让壁纸透出来——像桌面壁纸那样。顶部日期栏保持不透明，避免滚动时日程文字和壁纸糊在一起。

> 壁纸图片建议选**偏暗、色调统一**的，文字会更好读。压暗程度是可调常量，觉得太暗或太亮见第十二节常见问题。

### 这两项设置存在哪

单独存在 `desktop_pet_settings` 这个 LocalStorage 键里，**不掺进日程数据**。清除背景/壁纸不影响你的日程。

**注意**：「导出备份」只备份日程，**不包含背景和壁纸设置**。换设备后需要重新选一次。

## 十一、画中画

点顶栏 **「画中画」**，宠物舞台会被搬进一个独立的悬浮小窗，可以拖到屏幕任意角落、置顶在其他窗口之上，主窗口该干嘛干嘛。

搬过去的是**整个舞台**——背景、角色、头顶气泡、状态徽章全都在，跟主界面里一模一样。窗口下半部分还会带一条**紧凑计划栏**：列出今起三天内还没结束的安排（最多 5 条），正在进行的那条高亮，跨天的自动标上「明天 / 后天」。日程有增删改时它会立即刷新，时间流逝时每 30 秒更新一次。关闭小窗后舞台自动回到原位，视频播放不中断。

**关于位置**：浏览器没有提供"把画中画窗口固定到右上角"的接口，首次打开的位置由浏览器决定（通常在屏幕右下）。直接用鼠标把小窗**拖到右上角**即可，Chrome / Edge 一般会记住上次的位置，下次打开就还在那里。

**支持情况**：只有**桌面版** Chrome / Edge 116+ 和 Firefox 151+ 支持（用的是浏览器的 Document Picture-in-Picture API）。Safari、以及所有手机和平板浏览器都不支持——**不支持时按钮直接不显示**，不会点了没反应。

## 十二、常见问题

### 为什么我看到的是一只橙色小猫？

小猫是**内置的降级动画**。当 `videos/` 里的视频素材加载失败时，项目会自动切到它，保证功能可用。

按 `F12` 打开控制台可以看到具体原因：

| 控制台提示 | 含义 | 处理 |
| --- | --- | --- |
| `[Animation] 已启用视频素材 videos/*.webm` | 一切正常 | — |
| `[Animation] videos/idle.webm 加载偏慢…` | 读盘慢，先降级，加载好会自动切回 | 稍等即可 |
| `[Animation] 缺少 videos/xxx.webm，暂用 idle 素材代替` | 个别状态素材缺失 | 补上对应文件 |
| `[Animation] 未找到可用视频素材，已启用内置 SVG 角色动画` | 素材全都没加载上 | 见下 |

**排查顺序：**

1. **先按 `Ctrl+F5` 强制刷新**——如果你在素材生成之前就打开过页面，看到的是旧状态。
2. 确认 `desktop-pet/videos/zhenzhu/` 目录下确实有 7 个 `.webm` 文件（打开文件夹看一眼）。
3. **确认你是在浏览器里打开的，不是 IDE 的预览窗口**。IDE 预览不是真正的 `file://` 页面，读不到同级的 `videos/` 目录，必然降级成猫。
4. 想强制对比两种效果：加参数 `index.html?novideo=1` 会主动使用小猫。

更详细的原因和换装方法见 [第十七节](#十七虚拟形象自定义)。

### 数据存在哪里？会不会丢？

存在浏览器的 LocalStorage 里：

| 键名 | 存什么 |
| --- | --- |
| `desktop_pet_v2` | 你的日程数据 |
| `desktop_pet_settings` | 舞台背景、界面壁纸的选择（路径或 data URL），以及本地模型的开关/地址/模型名 |

背景/壁纸图片本身不在 LocalStorage 里：启用图片库后会写进 `data/backgrounds/`、`data/wallpapers/`；
只在浏览器兜底模式下才会以 base64 存进上面的设置键。目录授权句柄存在 IndexedDB 的
`desktop_pet_images` 库里（不存图片内容）。

关掉浏览器不会丢。**但清浏览器数据会丢**，所以建议定期点 **「导出备份」** 存一份 JSON。需要时点 **「导入备份」** 选回那个文件即可。

另外数据损坏时不会白屏：无法解析的内容会被自动备份到 `desktop_pet_v2_broken_<时间戳>`，然后以空列表启动。
数据版本比当前程序**更新**时（比如你用新版打开过、又换回旧版），同样会先备份到 `desktop_pet_v2_future_<时间戳>` 再启动，不会直接覆盖掉。

### 跨天的任务怎么填？

`end` 写成 `00:30(+1)` 表示次日凌晨 0:30 结束。计划表里会显示成 `23:00 - 次日 00:30`。

### 换了台电脑 / 换了浏览器，日程还在吗？

不在。LocalStorage 是按浏览器隔离的。用「导出备份」→「导入备份」迁移。背景和壁纸设置在备份之外，需要重新选。

### 怎么改"一个任务默认多长时间"之类的设置？

打开 `desktop-pet/app.js`，顶部的 `App.Config`（约 149-211 行）集中了所有可调项：

| 配置 | 当前值 | 作用 |
| --- | --- | --- |
| `defaultDurationMin` | `60` | CSV 里 `end` 留空时的默认时长（分钟） |
| `tickMs` | `1000` | 状态机检查间隔（毫秒） |
| `materializeDays` | `14` | 周期日程向后展开多少天 |
| `keywords` | 见文件 | 按标题自动归类的中文关键词表（`entertainment` 那一组就是娱乐词） |
| `entertainmentPatterns` | 见文件 | 娱乐词的宽松匹配正则，兜住「玩一会儿游戏」这种中间隔字的说法 |
| `refusePhrases` | 见文件 | 两级拒绝话术（含 `{category}` / `{title}` 占位） |
| `stateLabel` | 见文件 | 角色头顶徽章的文字。想改叫法改这里 |
| `stateByCategory` | 见文件 | 任务类别 → 基础态。想让「通用」类任务也显示学习状态，把 `general` 改成 `'studying'` |
| `tempMs` | `{alert:5000, done:3500, refuse:2500, warnStart:5000, warnEnd:4000, talking:90000}` | 各临时态的持续时间（毫秒）；`talking` 只是兜底上限，正常由回复结束主动收掉 |
| `startWindowSec` | `90` | 任务开始后多久内算"准点提醒" |
| `warnStartMin` | `5` | 任务开始前几分钟提醒 |
| `warnEndMin` | `10` | 任务结束前几分钟打气 |

**壁纸压暗程度**不在 `app.js`，在 `settings.js` 顶部的 `WALLPAPER_OVERLAY` 常量：

```js
var WALLPAPER_OVERLAY = 'linear-gradient(rgba(15,19,34,.35), rgba(15,19,34,.35)), ';
```

那个 `.35` 是压暗层的不透明度——**调小壁纸就更亮，调大变暗**。觉得壁纸不够显眼就往 `.25` 调，觉得刺眼就往 `.45` 调。

舞台背景的压暗层是另一个常量 `OVERLAY`（当前 `.32`），改法一样。

### 界面可以换多大的壁纸？

导入时自动等比缩放到最长边 1920 像素以内、转成 JPEG（质量 0.8）。所以放多大的原图都行，超过 20MB 的文件会被拒绝。

处理后的图会写进 `data/backgrounds/` 或 `data/wallpapers/`，设置里只存路径，**不再占 LocalStorage**。
如果当前打开方式不支持写文件夹，才会退回把压缩后的图存进 LocalStorage（面板会提示）——那种情况下建议选压缩后 1MB 以内的图。

### 宠物突然不动的？

先看你系统的**「减少动态效果」/「动画效果」**设置。Windows 在「设置 → 辅助功能 → 视觉效果」，macOS 在「系统设置 → 辅助功能 → 显示」。

这个项目会尊重系统的这个开关（`prefers-reduced-motion`）：**打开后所有动画都会被停掉**，宠物就定格了。这是有意为之，不是故障——对晕动症用户来说动画是负担。想恢复动画，把这个系统开关关掉即可。

## 十三、调试与演示参数

在 `index.html` 后面加参数即可，多个用 `&` 连接：

| 参数 | 例子 | 作用 |
| --- | --- | --- |
| `demo=1` | `index.html?demo=1` | 灌入演示日程，立刻看到工作/学习状态 |
| `time` | `index.html?time=14:30` | 假装现在是 14:30，用来演示特定时段的状态 |
| `date` | `index.html?date=2026-09-21` | 假装今天是某一天（配合 `time` 用） |
| `freeze=1` | `index.html?time=14:30&freeze=1` | 冻结时钟，时间停在 `time` 那一刻不再前进。**必须和 `time` 一起写**，单独写不生效 |
| `novideo=1` | `index.html?novideo=1` | 强制使用内置 SVG 小猫动画 |
| `nollm=1` | `index.html?nollm=1` | 本机跑着 Ollama 但想验证**离线路径**：即使开关开着也完全不连模型，待机、加日程、闲聊全部走原来的正则通路 |

**演示时最有用的一招**：先导入一份日程表，然后 `?time=<某个任务开始前一分钟>&freeze=1` 打开，再把 `freeze` 去掉刷新，就能完整看到"提醒 → 任务中 → 完成"的整条链路。

### 控制台里更灵活的调试钩子

浏览器按 F12 打开控制台，可以直接调 `App.debug`——比 URL 参数灵活，**不用刷新页面**：

| 命令 | 作用 |
| --- | --- |
| `App.debug.set('14:30', '2026-09-21')` | 把时钟拨到指定日期时间，当场看状态变化 |
| `App.debug.tick()` | 手动触发一次状态检查 |
| `App.debug.state()` | 打印当前状态快照（基础态、临时态、当前任务） |
| `App.debug.refuse()` | 手动播放一次拒绝动画（不用真的打字） |
| `App.debug.seed()` | 等同于 `?demo=1` 的灌数据 |

## 十五、使用建议

- **每天上班第一件事**：打开页面，看一眼右侧计划表，宠物已经在按今天的日程等你了。

### 先说结论：哪些能用，哪些不能

| 功能 | 电脑 | 手机 / 平板 |
| --- | --- | --- |
| 日程管理、对话指令、PDF / CSV 导入 | ✅ | ✅ |

| 宠物动画、七种状态 | ✅ | ✅ |

- **Android**：必须额外装一个 **QuickEdit** 当启动器，光用 Edge / Chrome 打开是用不了功能的（[见下文](#android-手机--平板)）
- **iPad / iPhone**：Files App 里点 HTML 读不到同目录的资源，要另想办法（[见下文](#ipad--iphone)）

**唯一不能用的是画中画**——那是浏览器桌面端专有的 API（`documentPictureInPicture`），Safari 和所有手机浏览器都没有实现（Android 上的 Chrome 也没有）。项目已经做了处理：**不支持时「画中画」按钮自动隐藏**，不会出现点了没反应的情况（[pip.js:56](../desktop-pet/pip.js#L56)）。

### Windows 平板（Surface 这类）

**和电脑完全一样，不需要任何额外步骤。**

1. 把 `desktop-pet` 文件夹拷到平板上
2. 双击 `desktop-pet/index.html`
3. 完成。画中画也能用

### Android 手机 / 平板

**Android 上光有浏览器不够，必须额外装一个 QuickEdit 当启动器。** 它不在应用商店里，**要用 Edge 打开网页搜索并下载安装**。只把 HTML 交给 Edge / Chrome 打开是**用不了功能的**，原因见下面。

1. **把整个 `desktop-pet` 文件夹拷进设备**——不是只拷 index.html，CSS、脚本、视频素材都在子目录里
   - 数据线连电脑直接拖
   - 或者用 U 盘 / 网盘中转
2. **用 Edge 搜索 QuickEdit，下载并安装**（应用商店里没有，走网页下载）
3. 在设备上打开**文件管理器**（系统自带的「文件」App）
4. 找到 `desktop-pet/index.html`，点它
5. 弹出「打开方式」时选 **QuickEdit**——**不要选 Edge / Chrome**
6. 在 QuickEdit 里打开 `index.html`，用它内置的浏览器预览，页面才能完整跑起来

**为什么必须多装这一个 App**：Android 上直接把 HTML 交给 Edge / Chrome 打开时，它们读不到同目录的 CSS、JS 和视频，结果是**页面能显示但没样式、没动画、点哪都没反应**——功能等于没有。QuickEdit 内置了浏览器预览，能按整个文件夹来读，所以功能正常。**这不是项目的问题，是 Android 打开本地 HTML 的通用限制**，换个项目也一样。

**三个坑：**

- **别在微信 / QQ 聊天记录里直接点 HTML 文件**。微信内置的预览器渲染不了完整页面，你会看到一堆源码或空白。必须先把文件存到设备本地，再用文件管理器打开。
- **「打开方式」必须选 QuickEdit**。选了 Chrome / Edge 会看到上面说的那种「能打开但功能全废」的页面，很容易误以为项目坏了。
- **如果点开是空白或只有文字**，说明没读到同目录的 CSS/JS。先检查是不是只拷了 `index.html` 一个文件——整个文件夹都要在；文件夹没问题的话，就是启动器没用 QuickEdit。

**加到主屏幕（像 App 一样打开）**：用 Chrome 打开后，右上角菜单 →「添加到主屏幕」。之后从桌面图标点进去，不用每次翻文件管理器。

> 注意两件事：这样加的是**书签快捷方式**，不是离线 App，文件被移动或删除后图标会失效；而且**这条只在页面能被浏览器正常打开时才有意义**——如果必须靠 QuickEdit 才能跑起来，那就只能每次从文件管理器点进去。

### iPad / iPhone

iOS 比 Android 麻烦：**Files App 里点 HTML 只会预览单个文件**，同目录的 CSS、JS、视频全都读不到，页面会散架。直接拷文件夹这条路走不通，有两个替代方案。

**方案 A：电脑起个本地服务器（推荐，最省事）**

要求：电脑和 iPad 连**同一个 Wi-Fi**，且电脑保持开机。

**优先用仓库自带的服务器**（零依赖，只需要 Node.js；同时开启图片自动同步）：

```bash
cd D:\AIcompete
npm run serve:lan        # 监听 0.0.0.0:8123
```

**查电脑的局域网 IP**：另开一个命令行窗口，输入 `ipconfig`，找「IPv4 地址」，形如 `192.168.1.5`。

**iPad 上**：Safari 地址栏输入 `http://192.168.1.5:8123/`（换成你查到的 IP）。

> 自带服务器默认监听 `127.0.0.1`；`serve:lan` 会允许局域网访问。图片写入接口**没有鉴权**，
> 只在你信任的局域网里使用，不用时把命令行窗口关掉。
> 这种模式下导入的图片会直接写进电脑上的 `data/backgrounds/`、`data/wallpapers/`。

如果只想用本机，`npm run serve` 即可；Windows 也可以双击 `start-server.bat`。

**备选：纯静态服务器**（没有图片写入接口，图片会退回目录授权 / 浏览器兜底）：

```bash
python -m http.server 8000
# 或
npx serve
```

用这种方式时 iPad 地址是 `http://192.168.1.5:8000/desktop-pet/`。

打不开的话，依次排查：

- 先确认电脑上的命令行窗口还开着（关掉窗口 = 服务器关了）
- Windows 防火墙可能拦了，弹窗时选「允许访问」
- 确认两台设备连的是同一个 Wi-Fi（手机热点不算）

**这个方案的缺点**：电脑必须开着，且 iPad 每次都得手动输网址。好处是 iPad 上的数据存在 Safari 里，不会丢。

**方案 B：用支持本地网站的 App**

App Store 里搜 **Koder**（或类似的代码编辑器 App，关键词 "local web server"）。

1. 把 `desktop-pet` 文件夹通过「文件」App 或 iCloud 传进 Koder
2. 在 Koder 里打开 `index.html`，用它内置的浏览器预览

不用电脑配合，但操作比方案 A 繁琐，App 也需要付费或看广告。

**iPhone 同理**：上面两个方案在小屏手机上同样适用。不过**竖屏手机上界面是单列的**，舞台在上、计划表在下，需要上下滚动——能用，但不如平板和电脑舒服。

### 移动端通用注意事项

**布局会自动适配**：屏幕宽度小于 900px 时，界面自动从「左舞台 + 右计划表」的双列切成上下单列（[style.css:921](../desktop-pet/style.css#L921)）。平板横屏（宽度通常 >900px）会保持桌面布局。

**提醒只在页面开着时响**：这跟设备无关，是项目的设计——提醒靠页面内的定时器，**你把浏览器切到后台或锁屏，提醒就不会响**。手机上尤其容易发生（切个微信就没了）。要让它一直提醒，得把页面保持在前台，且关闭系统的省电限制。

**数据不跨设备同步**：日程存在各自浏览器的 LocalStorage 里，按设备、按浏览器隔离。手机上打开是空的，跟电脑上的数据不互通。迁移方法：

1. 电脑上点顶栏 **「导出备份」**，得到一个 JSON 文件
2. 把文件传到手机（微信文件传输助手发给自己就行）
3. 手机上打开应用，点 **「导入备份」** 选那个文件

> 背景和壁纸设置**不包含在备份里**（备份只存日程）。手机上需要重新选一次，导入的本地壁纸图片也得重新导入。
> 手机浏览器通常拿不到目录授权，也没有配套本地服务器，所以导入的图会退回「只存在浏览器里」；
> 手机上手动放图也不方便，建议在电脑上放好、连同文件夹一起拷过去。

**触摸操作**：界面是按点击设计的，触摸屏上所有按钮都能正常点。输入框会自动弹出中文键盘，和平时打字一样。

## 十七、虚拟形象自定义

宠物的形象有两套（见[第六节](#六角色状态说明)）：**视频素材**（默认）和**内置 SVG 小猫**（降级用）。换形象分七种做法，按改动从小到大排：

| 想做的事 | 要动的东西 | 难度 |
| --- | --- | --- |
| 换回内置形象 zhenzhu | 顶部「更换形象」→ 点 zhenzhu 一行 | 不用改代码 |
| 应用内导入 / 切换形象包 | 顶部「更换形象」→ 导入 zip，形象存在浏览器本地 | 不用改代码 |
| 从网图制作可导入的形象包 | 豆包生成视频 → tools 处理 → zip 导入 | 不用改代码 |
| 换成自己画的角色（直接改内置目录） | 替换 `videos/zhenzhu/` 下 7 个视频文件 | 不用改代码 |
| 新增一个内置形象 | 在 `videos/` 下新建目录，并在 `character/builtin.js` 里加一项 | 改一行代码 |
| 换个造型 / 改动作 | 改 `character/animation.js` 的 SVG + `style.css` 的动画 | 改代码 |
| 改状态名称 / 时长 / 归类 | 改 `app.js` 的 `App.Config` | 改配置 |

### 素材规格（所有换装方式通用）

七个文件按状态命名：`idle` / `studying` / `working` / `alert` / `done` / `refuse` / `talking`。
每个状态优先 `.webm`，没有就找 `.mp4`，再没有就用包内/目录里的 `idle` 顶替，最后落到 SVG。
状态含义和徽章见[第六节](#六角色状态说明)。

| 要求 | 说明 |
| --- | --- |
| 格式 | 首选 WebM（VP9 + alpha，`-pix_fmt yuva420p`）；`.mp4` 必须 H.264，HEVC 在 Chrome / Edge 上解不了 |
| 背景 | 必须透明；黑底、白底都会被舞台看穿 |
| 尺寸 | 720×720 正方形最合适；非正方形按 `object-fit: contain` 缩放，四周留白 |
| 帧率/时长 | 24fps；基础态 5 秒左右且首尾能接上；临时态会被 `tempMs` 硬截断 |
| 体积 | 单个建议 < 3MB，避免本地加载卡顿 |

> 现有内置素材是 720×720 / 24fps，单段 4–10 秒；`refuse.webm` 有 10 秒，实际只播前 2.5 秒。
> 素材调试（文件名、控制台日志、降级原因）见 [desktop-pet/videos/README.md](../desktop-pet/videos/README.md)。

### 内置形象（默认 zhenzhu）

内置形象不走 zip、不占浏览器存储，应用直接按相对路径读 `desktop-pet/videos/<目录>/` 下的七个视频。
当前内置了 `zhenzhu`（`videos/zhenzhu/`），也是首次打开时的默认形象；顶部「更换形象」第一行即可切回。

**换掉 zhenzhu 的素材**：把七个文件按上面的名字放进 `desktop-pet/videos/zhenzhu/` 覆盖同名文件，
`Ctrl+F5` 刷新。想保留旧素材，先跑一次 `char_pack.py pack` 备份，或另建目录。

**新增一个内置形象**：在 `desktop-pet/videos/` 下新建目录，放进七个视频，然后在
`character/builtin.js` 的 `BUILTINS` 数组里加一行：

```js
{ id: 'my-char', name: '我的角色', dir: 'videos/my-char/', ext: '.webm' }
```

`Ctrl+F5` 刷新，面板里就会出现这一行。内置行不能删除，也不会写入 IndexedDB；
把目录删掉或改名后，应用会落到 SVG 或 `videos/` 根目录素材（如果存在）。

### 用形象包导入 / 切换（应用内操作）

形象包就是一个 **zip**：里面按状态名放视频，可带一份 `manifest.json` 描述名字/作者/版本/备注。

```
我的角色.zip
├── idle.webm
├── studying.webm
├── working.webm
├── alert.webm
├── done.webm
├── refuse.webm
├── talking.webm          # 七个状态可只放一部分
└── manifest.json         # 可选
```

`manifest.json` 示例（缺省时用 zip 文件名作形象名）：

```json
{
  "name": "我的角色",
  "author": "某人",
  "version": "1.0",
  "note": "备注",
  "created": "2026-10-17"
}
```

**操作**：双击 `index.html` → 顶部「更换形象」→「导入形象包（.zip）」。导入成功后自动切换；
列表里点任意一行即可换装，「✕」删除，「导出当前形象」把当前包重新打成 zip。
选择存在 `localStorage`，包体存在浏览器 **IndexedDB**（库名 `desktop_pet_packs`），
刷新/重开页面会自动恢复。**不会写入 `videos/` 目录**；清理浏览器站点数据会把导入的包一起清掉。

**校验是宽松的**（方便随手打包）：

- 允许任意子集，缺的状态用包内 `idle` 顶替；连 `idle` 都没有时尝试 `videos/idle.*`，再没有就落到 SVG
- 允许 zip 里套一层目录（如 `MyChar/idle.webm`），文件名归一规则比 `make_pet_videos.py` 更宽松：
  忽略大小写、空格、`-` 和 `_`，`studying .webm`、`Alert.MP4`、`work-ing.webm` 都能识别
- 同一状态出现多次：保留先出现的，并给出警告
- 上限：单个视频 10MB、解压后合计 50MB、zip 本体 60MB；超限文件跳过并警告
- 导入时逐个探测视频能否播放，坏的丢弃；全部播不了才拒收
- 非 WebM/MP4、`__MACOSX/`、`.DS_Store` 等自动忽略

**生成 zip** 用任意压缩工具都行：把 `<状态>.webm` 放在 zip 根目录，可带 `manifest.json`，
不要套多层目录。命令行更省事——完整命令、参数表以及 `list` / `install` 用法见下文第 5 步：

```bash
# 最简：把内置形象目录打包到 desktop-pet/videos/
python tools/video/char_pack.py pack
```

仓库里已放好两个 zip，都可以直接在「更换形象」里导入：

- `desktop-pet/videos/zhenzhu.zip` —— 当前内置形象 zhenzhu
- `desktop-pet/videos/_backup_20261017.zip` —— 旧版紫发少女素材

> 浏览器端不能把内置形象导出成 zip（`file://` 读不到 `videos/` 目录），所以内置行不提供导出；
> 要拿内置形象的 zip，用 `char_pack.py pack`。
> 需要解压 DEFLATE 条目的旧浏览器可能打不开非 STORED 的包，`char_pack.py` 默认就是 STORED。

### 从一张网图到形象包（豆包生成 + tools 处理）

想把网上的角色图变成可切换的形象，最短路径是：

**免费角色图 → 豆包生成七段状态视频 → `tools/video/make_pet_videos.py` 处理 → `char_pack.py` 打包 → 应用内导入。**

全程不用改代码。

> 图片请使用免费可商用素材，或你自己有权使用的图片；不要用未授权的真人肖像或他人作品。
> 豆包只是生成工具，素材版权责任仍在使用者。

#### 1. 准备角色图

- 选一张正面、全身或半身、轮廓清楚的角色图，背景越干净越好。
- 同一角色的七段视频最好都从**同一张图**生成，避免服装、画风在状态之间漂移。
- 图片建议先裁成正方形（如 1024×1024），方便后续生成 720×720 视频。

#### 2. 用豆包生成七段状态视频

打开豆包的「图生视频」（图片生视频）功能，上传角色图，按状态逐段生成。提示词里尽量写清：

- 保持同一角色、同一服装、同一画风；
- **纯白背景**——工具按白底抠图，背景不白会抠不干净；
- 固定机位，角色完整不出画；
- 正方形构图，约 5 秒；
- 对应状态的动作，见下表。

| 状态 | 建议文件名 | 动作 |
| --- | --- | --- |
| 空闲 | `idle.mp4` | 轻微呼吸、眨眼，首尾姿态一致 |
| 学习中 | `studying.mp4` | 看书、写字、翻页 |
| 工作中 | `working.mp4` | 打字、敲键盘 |
| 提醒 | `alert.mp4` | 抬头、举手或指向某处 |
| 完成 | `done.mp4` | 开心、比手势、庆祝 |
| 拒绝 | `refuse.mp4` | 摆手、摇头 |
| 交流中 | `talking.mp4` | 说话、口型变化 |

- 基础态（idle / studying / working）会循环播放，**首尾帧要能接上**；临时态（alert / done / refuse）
  只播一轮，时长上限分别是 5s / 3.5s / 2.5s，生成太长会被截断。
- 豆包视频通常带「豆包AI生成」水印，下一步的工具会自动去水印；水印样式不同时用
  `--no-watermark` 跳过，再手动处理。

#### 3. 用项目工具处理视频

工具是 `tools/video/make_pet_videos.py`，需要 Python 3.10+ 和三个依赖：

```bash
pip install numpy opencv-python-headless scipy
```

**输入**可以是整个目录，也可以是单个视频文件。目录只扫一层、不递归子目录；
支持的输入扩展名是 `.mp4` / `.webm` / `.mov` / `.mkv` / `.avi`，输出统一为 `.webm`。

```bash
# 处理整个目录（只处理文件名能识别成七种状态之一的视频）
python tools/video/make_pet_videos.py 我的视频 --out new_video/processed

# 只处理一个文件
python tools/video/make_pet_videos.py "我的视频/studying .mp4" --out new_video/processed

# 直接写进内置形象目录（会覆盖同名文件，先备份！）
python tools/video/make_pet_videos.py 我的视频 --out desktop-pet/videos/zhenzhu
```

文件名规则：去掉扩展名、去掉首尾空格、转小写；`studying .mp4`、`Alert.MP4` 都能识别，
其它名字会跳过并提示。每个输入按状态名输出 `<状态>.webm`。

工具会依次完成：**去水印 → 白底转透明（保留角色内部白色）→ VP9 + alpha 编码
（720×720 / 24fps）→ 校验 alpha**。常用参数：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `input` | 必填 | 输入目录或单个视频文件 |
| `--out` | 必填 | 输出目录 |
| `--ffmpeg` | 自动 | 指定 ffmpeg 路径 |
| `--fps` | `24` | 抽帧与编码帧率 |
| `--crf` | `34` | VP9 质量；越大体积越小、越糊 |
| `--tol` | `32` | 白底容差；背景没抠干净调大，角色白色被吃掉调小 |
| `--feather` | `0.8` | 边缘羽化像素 |
| `--watermark` | `assets/doubao_watermark.npz` | 水印模板 |
| `--watermark-high` | `0.05` | 水印命中阈值；漏删调低 |
| `--watermark-low` | `0.02` | 淡入淡出延展阈值 |
| `--no-watermark` | 关 | 跳过去水印（水印样式不同或已手动处理时） |
| `--no-bg` | 关 | 跳过抠背景，只转码 |
| `--keep-frames` | 关 | 保留中间帧，便于排查 |

运行时会逐个文件打印结果：

```
[处理] idle.mp4 -> idle.webm
  120 帧 / 5.00s / 820 KB / yuva420p / alpha 0-255 透明 62% / 去水印 120 帧
...
完成 7 个，失败 0 个，输出：new_video/processed
```

- `alpha` 的透明占比取决于角色占画面的比例；如果接近 0%，说明背景没被抠掉。
- 退出码：全部成功为 0，有文件失败为 1，便于脚本化调用。
- ffmpeg 查找顺序：`--ffmpeg` → 环境变量 `FFMPEG` → `tools/video/ffmpeg.exe` → `PATH` →
  `imageio-ffmpeg`。本机已带 `tools/video/ffmpeg.exe`（约 84MB，已被 `.gitignore` 排除）。
- Windows 终端中文乱码时，命令前加 `PYTHONIOENCODING=utf-8`。
- 输出目录 `new_video/processed/` 是临时目录（已 gitignore），导入后可以删掉；
  不要直接写进 `desktop-pet/videos/zhenzhu/`，除非你已经用 `char_pack.py pack` 备份过旧素材。
- 加 `--keep-frames` 会在输出目录下保留抽帧 PNG，处理完不自动删；排查水印或抠图问题时用。
- 完整说明与水印模板标定方法见 [tools/video/README.md](../tools/video/README.md)。

#### 4. 检查输出

终端会打印每个文件的帧数、时长、体积、`pix_fmt` 和 alpha 占比；**任一文件没有透明像素会给出警告**。
播放检查时，透明背景应该能透出后面的内容，而不是黑底。需要手动确认 alpha：

```bash
tools/video/ffmpeg.exe -c:v libvpx-vp9 -i new_video/processed/idle.webm
```

看到 `yuva420p` 才算对。直接用 `ffmpeg -i` 可能显示 `yuv420p`，那是内置 vp9 解码器不读 alpha，
不是文件坏了。

#### 5. 打成形象包

`char_pack.py` 只用 Python 标准库，不需要再装 numpy / opencv。

**打包**：

```bash
python tools/video/char_pack.py pack --name "我的角色" --videos new_video/processed --out desktop-pet/videos
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--name` | `默认形象-紫发少女` | 形象名，同时作为 zip 文件名 |
| `--author` | 空 | 写入 `manifest.json` |
| `--version` | `1.0` | 写入 `manifest.json` |
| `--note` | 空 | 写入 `manifest.json` |
| `--videos` | `desktop-pet/videos/zhenzhu` | 素材目录 |
| `--out` | `desktop-pet/videos` | zip 输出目录 |
| `--method` | `stored` | `stored` 兼容性最好；`deflated` 体积更小，但旧浏览器可能打不开 |

打包时按七种状态的顺序收集，每个状态优先 `.webm`、其次 `.mp4`；缺状态会在终端提示，
zip 里只放现有的。`manifest.json` 会自动写入 `name / author / version / note / created`。
`pack` 只扫 `--videos` 顶层，文件名必须是精确的 `<状态>.webm` / `<状态>.mp4`，不会像应用内导入
那样归一化空格或连字符。

**查看包内容**：

```bash
python tools/video/char_pack.py list desktop-pet/videos/我的角色.zip
```

会打印 manifest 和每个条目识别出的状态、大小，用来确认文件名没有写错。

**安装回磁盘（可选）**：

```bash
python tools/video/char_pack.py install desktop-pet/videos/我的角色.zip
```

默认解压到 `desktop-pet/videos/zhenzhu/`，只覆盖 zip 里出现的状态，其余素材保持不动；
覆盖前会把旧文件复制到 `desktop-pet/videos/_backup_<日期>/`。可以用 `--videos <目标目录>` 改安装位置。
如果只是应用内导入，不需要这一步。

#### 6. 导入并切换

回到本节开头的「用形象包导入 / 切换」：顶部「更换形象」→「导入形象包（.zip）」→ 选刚生成的 zip。
导入成功后自动切换，刷新页面也会恢复。

想让它成为**内置形象**（不占浏览器存储）：把 webm 放进 `desktop-pet/videos/我的角色/`，
再在 `character/builtin.js` 的 `BUILTINS` 里加一行，详见上文「内置形象」。

### 改 SVG 小猫的造型和动作

视频素材全都加载不上时会用这套内置动画，也可以主动加 `?novideo=1` 强制启用。

**造型**在 `desktop-pet/character/animation.js` 的 `svgMarkup()` 函数里（约 21-120 行），是一整段内联的 SVG 字符串，画布 `viewBox="0 0 200 200"`。里面分好了组，改颜色/改形状直接编辑对应分组：

| 分组 | 部位 |
| --- | --- |
| `g-tail` | 尾巴 |
| `g-body` | 身体 |
| `g-head` | 头 |
| `g-arm` | 手臂。实际有两个：`g-arm arm-l`（左）和 `g-arm arm-r`（右），CSS 里按 `arm-l` / `arm-r` 单独控制所以能做出左右手不同动作 |
| `prop-book` | 学习状态显示的书 |
| `prop-keyboard` | 工作状态显示的键盘 |
| `sign-exclam` | 提醒状态的感叹号 |
| `sign-cross` | 拒绝状态的 ✕ 符号 |
| `sparkle` | 完成状态的星光 |

**动作**（每个状态怎么动）在 `desktop-pet/style.css` 约 716-917 行，选择器形如：

```css
.stage[data-state="studying"] .arm-r {
  transform-origin: 30% 30%;
  animation: page-flip 2.2s ease-in-out infinite;
}
```

`.stage[data-state=...]` 前缀决定"什么时候动"，后面的类名决定"谁动"
（`.pet-all` 整体、`.g-head` 头、`.arm-l` / `.arm-r` 左右手、`.prop-book` 书本……）。
想改动作就改 `animation` 引用的那个 `@keyframes`（这里是 `page-flip`）。

改完记得 `Ctrl+F5` 刷新。

相关配置都在 `desktop-pet/app.js` 的 `App.Config`（约 149-211 行）：
`stateLabel`（徽章文字）、`stateByCategory`（类别 → 基础态）、

每一项的含义见[第十二节](#怎么改一个任务默认多长时间之类的设置)的完整表格，这里不再重复。

### 换形象时的常见问题

**换了新素材但没生效？** 99% 是缓存。按 `Ctrl+F5` 强制刷新。还不行就检查文件名大小写。

**临时态播到一半就切走了？** 临时态的播放时长受 `App.Config.tempMs` 上限约束。素材比上限长的话会被截断——要么把视频剪短，要么调大 `tempMs` 里对应的值。

**非正方形的素材会怎样？** 不会被裁剪，按比例缩放到装得下为止，四周留白。想填满舞台就用正方形素材。

**看到的是橙色小猫？** 那是降级动画，原因和排查见[第十二节](#为什么我看到的是一只橙色小猫)。

## 十八、本地大模型（Ollama）

前面所有功能都**不联网**——说话靠 `dialog/input.js` 里的中文正则匹配。正则能接住「明天下午两点半上英语课」这种规整说法，接不住「这周找个时间把论文初稿弄完」这种没写明时间的句子，也不会闲聊。

**接一个本地模型就能补上这两块**：你随便怎么说它都能听懂，还能陪你聊天、结合你的日程回答问题。模型跑在你自己电脑上，**对话内容不出局域网**。

> **默认是关的。** 关着的时候不产生任何网络请求，行为和装这个功能之前一模一样。上面所有文档在开关关闭时都成立。

### 三步开起来

**1. 装 Ollama 并拉一个模型**

到 <https://ollama.com/download> 下载安装（Windows / macOS 都有）。装完打开终端：

```bash
ollama pull qwen3:4b
```

`qwen3:4b` 约 2.5GB，纯 CPU 也能跑，是默认值。机器有独显、内存 16GB 以上可以换 `qwen3:8b`（约 5GB，答得更稳但更慢）；内存小的老机器用 `qwen3:1.7b`（约 1.4GB，快但容易答歪）。**换模型前必须先 `ollama pull` 把新模型拉到本地，页面只负责填名字连过去，不会替你下载。**

**2. 允许浏览器跨源访问**

用 `file://` 双击打开页面时，浏览器会因为同源策略拦掉对 `127.0.0.1:11434` 的请求。设置一个环境变量再重启 Ollama：

```powershell
# Windows PowerShell（设完要退出托盘里的 Ollama 再重新打开）
setx OLLAMA_ORIGINS "*"
```

```bash
# macOS / Linux
export OLLAMA_ORIGINS="*"
```

`*` 只表示"谁都能连我这个本地端口"，而 Ollama 默认只监听本机，**不会因此把模型暴露到公网**。

> **设完必须真的重启 Ollama（退出托盘图标再打开）**。环境变量只在进程启动那一刻读一次，
> 正在跑的那个进程不会自己更新——不重启，页面会一直停在「未连接」，看起来像设置没生效。
>
> **不想设环境变量也行**：用仓库自带的 `npm run serve`（`http://127.0.0.1:8123/`），
> 或 `cd desktop-pet` 后跑 `python -m http.server 8080`（`http://localhost:8080/`）——
> Ollama 默认就放行 localhost 来源。
> 但 `file://` 和 `http://localhost:*` 是**两个独立的存储空间**，原来双击时存的日程
> 在新地址下看不到。要带过去：双击打开 → 顶部「导出备份」下载一个 JSON → 换 HTTP 地址打开 → 「导入备份」。
> 同理，`file://` 下授权的图片目录和 HTTP 模式下的图片库也是两套，互不影响。

**3. 在页面里打开开关**

顶部工具栏点 **「本地模型：关」**，按钮变绿、文字变成「本地模型：开」：

| 步骤 | 你会看到 |
| --- | --- |
| 点「本地模型：关」 | 按钮变绿写「本地模型：开」，底部提示「本地模型已开启，正在检测连接…」，宠物说「本地模型开啦～」 |
| 探活（`GET /api/tags`，2.5 秒超时） | 徽章显示「检测中…」 |
| 结果 | 通 →「已连接（N 个模型）」；**通但没这个模型 →「已连接，但没有 xxx」**；不通 →「未连接」 |

探活不只看端口通不通，还会**核对模型名在不在返回的清单里**——开着模型却在跟一个没下载的模型名对话时，徽章和面板里都会说清楚（见下面的[三种出错情形](#三种出错情形分别会看到什么)）。

**模型名要自己填。** 点 **⚙** 展开设置面板：

| 字段 | 怎么填 |
| --- | --- |
| 接口地址 | 默认 `http://127.0.0.1:11434`，模型装在本机就不用改。装在局域网另一台机器上填 `http://192.168.x.x:11434` |
| 模型名 | 手输，默认 `qwen3:4b`。**先 `ollama list` 看一眼有哪些**，名字要一模一样（含 `:4b` 这样的标签） |
| 「保存」 | 写进浏览器存储，并立刻重新探活 |
| 「重新检测」 | 不改配置，只重新打一次探活 |

模型名输入框带自动补全：探活成功后，Ollama 返回的模型清单会灌进候选里，点一下就能选，不用手打全名。

> **模型名打错或没下载，都不会悄悄失败。** 徽章变成「**已连接，但没有 xxx**」，下面还有一行提示直接给命令：`ollama pull xxx`，并列出你已经装了哪些。修好之后点「重新检测」（或「保存」）就会恢复。

### 三种出错情形，分别会看到什么

模型不可用时**不影响任何原有功能**——加日程、提醒、导入导出走的还是原来那套正则。但页面会把"为什么用不了"说清楚，而不是让你以为是自己的说法有问题：

| 情形 | 徽章 | 面板提示 | 在聊天窗里问「你好」 |
| --- | --- | --- | --- |
| **模型没下载**（名字打错 / 忘了 pull） | 已连接，但没有 xxx | 在终端运行 `ollama pull xxx`，再点「重新检测」。当前已安装：… | 「本地模型还没安装「xxx」，这条先按离线模式处理。在终端运行 ollama pull xxx…」 |
| **连不上**（Ollama 没启动、地址写错） | 未连接 | 连不上接口。确认 Ollama 已启动，然后点「重新检测」 | 「本地模型连不上，已使用离线模式。确认 Ollama 已启动后，在设置里点「重新检测」。」 |
| **模型答不上来** | 已连接（N 个模型） | —— | 模型自己的回答；真答不上来时给「这个问题我暂时答不上来～换个问法试试？」 |

三条提示都是**状态一变就说一次**，不会每问一句刷一遍。

> 端点接口地址和 HTTP 状态码只出现在设置面板里，不进聊天窗——出问题时你需要的是一句能照做的话，不是一串端点 URL。

**不用 Ollama 也行。** 只要对方的 `/api/chat` 兼容 Ollama 的协议，接口地址填过去就能用；某些实现没有 `/api/tags`，探活会返回 404，这种情况**照样算连上**，只是读不到模型清单（徽章写「已连接（读不到模型列表）」），模型名得自己填准。

### 打开之后有什么不一样

| 场景 | 关着 | 开着 |
| --- | --- | --- |
| 「明天下午三点到四点项目评审会议」 | 正则接住，直接建日程 | 正则先接，同样的结果 |
| 「**这周找时间**把论文初稿弄完」 | 听不懂，回「没太听懂」 | 模型补全意图，**复述给你确认**，回复「确认」才建日程 |
| 「我今天还有什么安排」 | 正则接住，列出清单 | 同上（模型不参与） |
| 「你好呀，今天心情怎么样」 | 听不懂 | 聊天回复，边生成边显示 |
| 「我明天有什么要做的？」 | 听不懂 | 结合你的日程表回答 |

**三个关键设计**：

- **正则优先，模型兜底**。只有正则没接住的句子才会送给模型。所以常用说法永远是**毫秒级**响应，模型再慢也不拖累它们。
- **模型不直接写数据**。它只输出一个意图对象，后面照样走 `App.Controller` 里那些 `do*` 处理器——冲突检测、重叠询问、娱乐拦截全都还在。**不会出现"模型把日程写乱了"这种事**。
- **模型解析出的写操作，先复述再执行**。4B 模型会理解错，而删错、改错一条日程的代价比多问一句大得多，所以添加 / 修改 / 删除 / 复制都会先跟你对一遍，回复「确认」才落库。查询（「今天有什么安排」）和闲聊是只读或纯文字，不拦，直接答。

```
你：这周找时间把论文初稿弄完
宠物：我理解你要添加 周五 14:00–15:00「论文初稿」，对吗？（回复「确认」或「取消」）
你：确认
宠物：好的，已添加 周五 14:00–15:00 论文初稿（学习）。
```

> 具体日期时间是**模型补的**，觉得不对不用重新组织语言，直接说对的说法（比如「改成周六上午」）——待确认就撤掉，这句按新指令处理。
> 关掉模型时同一句话仍是「没太听懂」：确认门只装在模型通路上，正则通路只在自己有把握时才接住，解析出来直接执行。

### 它有多慢？

本地小模型的速度取决于你的硬件。**纯 CPU 推理时实测**（qwen3:4b，643 token 的意图提示词）：

| 阶段 | 耗时 |
| --- | --- |
| 读提示词（prompt eval） | 约 9.5 秒 |
| 生成 48 token 的意图 JSON | 约 3.2 秒 |
| **一次加日程总计** | **约 13 秒** |

有独显（GPU 加速）会快一个量级，通常在 1~3 秒内。聊天更慢一点，但**是流式输出的**——第一个字大约 3 秒出现，然后边生成边往外蹦，不用干等。

等待期间宠物会切成「交流中」状态循环播放 `talking.webm`，对话框上面显示「让我想想…」，所以不会看起来像卡死了。

**如果超过 30 秒还没出结果**，会判超时：状态降级为「未连接」，这句话退回离线通路处理，而不是石沉大海。

### 复读守卫：为什么它不会把上一条原样再吐给你

小模型（尤其 `qwen3:4b`）在带多轮上下文时有个毛病：**逐字照抄自己上一条回复**。实测走真实路径连问 6 个互不相关的问题，复读率 **80%**；把历史折进系统提示、加「不要重复」指令、降低 temperature 都压不住（仍是 13%），**只有完全不带历史的请求是 0%**。

所以项目不跟模型较劲，而是加了一道确定性守卫：

1. 回复收全后，跟上一条 assistant 回复逐字比对
2. 一样 → **清屏、丢掉历史重问一次**（等价于那个 0% 的形态）
3. 重问还是照抄 → 不把照抄的内容留在屏幕上，改成「这个问题我暂时答不上来～换个问法试试？」，这一轮也不写进对话历史

代价是触发的**那一轮**会丢掉多轮上下文，语气可能更死板——但比把上一句原样再吐一遍强。你连着问同一句话时，模型答同一句是对的，守卫不会误伤。

### 出问题了

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 徽章一直「未连接」 | Ollama 没启动 / 地址不对 | 看托盘里有没有 Ollama；命令行跑 `ollama list` 确认能通 |
| 徽章写「已连接，但没有 xxx」 | 模型名打错，或者还没 `ollama pull` | 按面板里的提示跑 `ollama pull xxx`，再点「重新检测」 |
| 提示要设 `OLLAMA_ORIGINS` | 浏览器拦了跨源请求 | 见上面第 2 步，**设完必须重启 Ollama** |
| 之前能用，突然「未连接」 | Ollama 重启后没加载模型，或端口被占 | 点 ⚙ 里的「重新检测」 |
| 问「你好」「今天天气怎么样」，回「我答不上来，本地模型现在用不了」 | 模型不可用，这几句本来要靠它回答 | 按提示修好模型；关掉开关则回到「没太听懂」的原文案 |
| 回复里带一堆"首先…让我想想…" | 不是本项目的 bug，是模型在"思考" | 项目已经用 JSON 结构约束压制住了；换成更大的模型（`qwen3:8b`）更稳 |
| 答非所问 / 重复上一句 | 小模型的固有问题 | 项目有复读守卫兜底；换 `qwen3:8b` 更稳 |
| 每次回答都很慢 | 纯 CPU 推理 + 模型太大 | 换 `qwen3:1.7b`，或让 Ollama 用上独显 |

**连不上会不会影响正常用？** 不会。探活失败只是把按钮显示成「未连接」，你照样能加日程、看提醒、导入导出——走的还是原来那套正则。

### 隐私

- 请求只发给**你自己填的地址**，且必须是本机或局域网地址（`localhost` / `127.*` / `10.*` / `192.168.*` / `172.16-31.*`）。填公网地址会被拒绝并回落到默认值——这是防止设置被篡改后把你说的话发到外网。
- 发给模型的内容有三块：你的那句话、你的日程清单（今天+明天+后天，最多 30 条）、最近 12 轮对话。
- **对话记录只存在内存里**，刷新页面就没了，不写 LocalStorage，也不落盘。
- 开关关着的时候，以上全部不发生。

### 想调参 / 想验证

可调项在 `App.Config.llm`（`desktop-pet/app.js`）：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `healthTimeoutMs` | `2500` | 探活超时 |
| `intentTimeoutMs` | `30000` | 意图提取超时。纯 CPU 上实测要 13 秒，别调太小 |
| `chatTimeoutMs` | `90000` | 聊天回复总超时（也是「交流中」动画的兜底上限） |
| `intentMaxTokens` | `256` | 意图 JSON 的输出上限 |
| `chatMaxTokens` | `512` | 聊天回复的长度上限 |
| `historyTurns` | `12` | 记着最近多少轮对话 |
| `contextTaskDays` | `3` | 提示词里带几天的日程（今天+明天+后天） |
| `contextMaxTasks` | `30` | 提示词里最多列几条任务 |

想验证接得通不通，在仓库根目录跑：

```bash
npm test                      # 离线：全部 14 个套件 803 条断言，不联网。test-llm.js 占其中 219 条
npm run test:live             # 联网：真连 Ollama 跑一遍完整链路（42 条）
```

`test-llm-live.js` 需要 Ollama 在跑。连不上、或者模型没 pull，它会**打印跳过原因并以退出码 0 结束**，不会让回归挂掉。想指定地址或模型：

```bash
OLLAMA_ENDPOINT=http://192.168.1.9:11434 OLLAMA_MODEL=qwen3:8b npm run test:live
```

**改了提示词或换了模型之后，跑一次 live 测试**——离线测试里模型是打桩的，管不到"真模型听不听话"。

> 写模型相关的断言时注意：`soft()` 只打印警告、**不影响退出码**，适合"模型措辞好坏"这类主观判断；但凡是**确定性**的东西（状态机、提示文案、复读），一律用 `check()` 硬断言。
> 复读那条断言最初写成 `soft` 并留了「允许 1 次重复」的余地，结果残余的复读一直没被发现，直到走真实路径单测才暴露出来——见开发记录第十六篇。
